# หุ้นต่างประเทศยึดหน้า AI Portfolio Manager — design

วันที่ 2026-11-09 · สถานะ: ผู้ใช้สั่ง "แก้เลย" (ข้ามการถามต่อ) หลังยืนยันประเด็นหลักแล้ว

## เจตนา

ผู้ใช้อัปเดตมูลค่าหุ้นต่างประเทศรายตัวในหน้า AI Portfolio Manager (PM) บ่อยกว่า Quarterly Editor ที่กรอกรายไตรมาส ตัวเลขหุ้นต่างประเทศบนหน้าอื่นจึงดูเก่า ผู้ใช้ต้องการให้ **หุ้นต่างประเทศทุกที่ยึดหน้า PM** โดยเพิ่มช่อง **cash** ในหน้า PM

คำพูดผู้ใช้ (ตามลำดับ):
- "ปรับความสัมพันธ์ของข้อมูลหน้า AI Portfolio manager ให้ยึดหน้า AI Portfolio manager โดยให้เพิ่ม cash อีก field นึง เพื่อที่หน้า portfolio position จะได้ดึงส่วนของ Asset allocation จาก AI Portfolio manager แทน แต่ Quarterly editor ก็ยังให้กรอกเองนะ"
- "เฉพาะหุ้นต่างประเทศเท่านั้น"
- ยืนยันภาพ: cash = เงินที่กันไว้รอซื้อหุ้นต่างประเทศ · แท่งหุ้นต่างประเทศ = มูลค่าหุ้นทุกตัวใน PM (ลงทุนแล้ว) + cash (รอซื้อ) · หน้า PM คิดเงินสดพร้อมวางจากช่องนี้แทนการเอา Editor มาลบ — "ถูกต้องงงง"
- "สำหรับหุ้นต่างประเทศเปลี่ยนทั้งหมด ให้ยึดจากหน้า AI portfolio ไปเลย"
- ผลตอบแทนรายไตรมาส / เป้าเกษียณ ยังคิดจาก Quarterly Editor (ผู้ช่วยแนะนำ · ผู้ใช้ตอบ "แก้เลย")

## นิยาม

- **หุ้นต่างประเทศ (PM)** = holdings ที่ `isHolding` และ bucket = `foreign-stock` ตามกติกาเดิมของหน้า PM (`portfolioBucket` ที่ตั้งเองชนะ · `.BK` = หุ้นไทย · มี "BTC" = bitcoin · RMF/SSF/กองทุนไทย = กองทุนไทย · ที่เหลือ = หุ้นต่างประเทศ · GOOG + GOOGL นับทั้งคู่)
- **invested** = Σ `marketValue` ของหุ้นต่างประเทศ (PM)
- **cash** = ช่องใหม่ในหน้า PM = เงินที่กันไว้รอซื้อหุ้นต่างประเทศ (บาท ≥ 0 · 0 = กรอกแล้วว่าเป็นศูนย์)
- **gross** = invested + cash · invested% = invested / gross

## พฤติกรรม

1. **ที่เก็บ cash:** เอกสารพอร์ตบน server (`/api/portfolio`) คีย์ `foreignSleeve = { cash, updatedAt }` (ทุกเครื่องเห็นเลขเดียวกัน) · บันทึก = GET สด → เอกสารไม่มีไตรมาส = ไม่ PUT → สำเนาทุกคีย์ → ตั้ง `foreignSleeve` → PUT · ล้มเหลว = ร่างใน localStorage + ปุ่มลองใหม่ (แบบเดียวกับกรอบเงินสดของการ์ด Asset allocation) · Quarterly Editor (app.js) ต้องคง `foreignSleeve` ที่อยู่บน server ตอนบันทึก (แบบ `allocation`/`allocationPlan`)
2. **โหมด:** `pm` เมื่อ cash ถูกกรอกแล้ว **และ** มีรายการ holdings โหลดอยู่ (array ไม่ว่าง) · ไม่งั้น `editor` = พฤติกรรมเดิมทุกอย่าง (ยังไม่กรอก cash หรือ holdings ยังไม่มา — ห้ามแสดงหุ้นต่างประเทศ = cash ล้วน)
3. **ตัวเลขปัจจุบันทุกหน้า** ในโหมด pm ใช้ gross/invested/cash ของ PM แทนแถว `foreign-stock` ของไตรมาสปัจจุบันใน Editor: หน้า PM (ฐาน % / เงินสดพร้อมวาง) · Portfolio Position (ส่วนหัว · แถบสัดส่วนพอร์ต · การ์ด Asset allocation) · Home/Mission Control · Action Center · Accumulation Center · หน้ารายหุ้น (thesis reconcile) · Adaptive Position
4. **ไม่เปลี่ยน:** Quarterly Editor (กรอกเอง) · ผลตอบแทนรายไตรมาส / เป้าเกษียณ / ตารางบันทึกผลตอบแทน (ส่วน Asset Allocation ด้านล่าง /portfolio และบรรทัดการเติบโตในส่วนหัวที่อ่านจากมัน) · ไตรมาสที่ผ่านมาใน Editor · QoQ = ปัจจุบัน (PM) เทียบไตรมาสก่อน (Editor)
5. **บอกที่มา:** ที่ใดแสดงหุ้นต่างประเทศในโหมด pm ให้มีข้อความสั้นว่ามาจาก AI Portfolio Manager (อย่างน้อย: ส่วนหัว/แถบของ Portfolio Position · ท้ายการ์ด · คำอธิบายในหน้า PM) · หน้า PM โหมด editor บอกว่า "ยังไม่ได้กรอกเงินสด — ตอนนี้ใช้ยอดจาก Quarterly Editor"
6. **Privacy Lock:** ช่อง cash ตอนล็อก = ว่าง + placeholder "ล็อกอยู่ — ใส่ค่าใหม่ได้" · เว้นว่างตอนบันทึก = คงค่าเดิม · เงินที่แสดงเป็น ฿ text node ให้ privacy.js ซ่อน · ห้าม ฿ ใน title/aria-label

## Anti-goals

- ห้ามเขียนเอกสารที่ถูกแปลง (แถวหุ้นต่างประเทศสังเคราะห์) กลับลง server — ผู้เขียนทุกตัวต้อง GET สดก่อน PUT
- ห้ามแตะประวัติไตรมาสใน Editor
- ห้ามคำแนะนำซื้อขาย

## ที่เหลือให้ผู้สร้างตัดสิน

ตำแหน่งช่อง cash บนหน้า PM (ข้อเสนอ: ในการ์ดสถิติ "ลงทุนแล้ว · เงินสดพร้อมวาง" ด้านบน) · ข้อความที่มาบนแต่ละหน้า · รูปแบบการแจ้งร่าง/ลองใหม่ (ลอกจากการ์ด Asset allocation)

## Addendum 2026-11-09 — Quarterly Editor ตาม PM ด้วย (ผู้ใช้เลือก "แบบ 1")

หลัง push ผู้ใช้เห็นว่าแถวหุ้นต่างประเทศในหน้า Quarterly Editor ไม่เปลี่ยนตาม PM ("หุ้นต่างประเทศ หน้านี้ ไม่เปลี่ยนตาม ai portfolio นะ") ผู้ช่วยเสนอ 2 แบบ ผู้ใช้ตอบ "เอาแบบ 1":

1. **แถวหุ้นต่างประเทศของไตรมาสปัจจุบันใน Editor ตาม PM อัตโนมัติ** — มูลค่ารวม + % ลงทุนจริง มาจาก PM แก้ในหน้า Editor ไม่ได้ (ลบไม่ได้ · เพิ่มแถวหุ้นต่างประเทศใหม่ไม่ได้) · เงินเติม/ถอนสุทธิ และชื่อ ยังแก้ได้ · สินทรัพย์อื่นกรอกเองเหมือนเดิม · ค่าที่ซิงก์เก็บลงเอกสารเมื่อ Editor บันทึกครั้งถัดไป (ไม่บันทึกเองตอนเปิดหน้า) · กด "บันทึกไตรมาส" = ค่าจาก PM ถูกแช่เป็นประวัติ
2. **ผลตอบแทนรายไตรมาส / เป้าเกษียณ ใช้ค่า PM ของไตรมาสปัจจุบันด้วย** (แทน §4 เดิม) — ไตรมาสที่ผ่านมาใช้ค่าที่แช่ไว้เหมือนเดิม · ป้าย "(ตาม Quarterly Editor)" / หมายเหตุผลตอบแทนเดิมเอาออก
3. **ตัวตนของแถวต้องต่อเนื่อง:** แถวที่แทนด้วยค่า PM ใช้ชื่อ/ตัวตนของแถวหุ้นต่างประเทศเดิม (แถวแรก) ไม่ใช่ชื่อใหม่ — ตัวคิดผลตอบแทนจับคู่รายการข้ามไตรมาสด้วย type+name ถ้าชื่อเปลี่ยน ระบบจะเห็นเป็น "ขายของเก่า ซื้อของใหม่" แล้วประมาณเงินเติมผิด · เงินเติม/ถอนของแถวเดิมรวมเข้าแถวที่แทน
4. **ใช้ค่า PM เฉพาะไตรมาสล่าสุด** — ถ้า Editor เลือกดูไตรมาสเก่า (มีไตรมาสใหม่กว่า) ห้ามเอาค่าวันนี้ไปทับไตรมาสนั้น (ทุกหน้า = โหมด editor สำหรับกรณีนี้)
5. **ไตรมาสที่จบตามปฏิทินแล้วไม่รับค่า PM** (ผู้ช่วยตัดสินหลังรีวิว Task 2) — ถ้าไตรมาสปัจจุบันของเอกสารเก่ากว่าไตรมาสตามปฏิทินวันนี้ (เช่น ยังเป็น 2026-Q3 ในเดือน พ.ย.) ทุกหน้าใช้ค่าที่เก็บใน Editor และ Editor ไม่ซิงก์ — กันค่าวันนี้ไปทับประวัติไตรมาสที่ปิดแล้ว (เคส: เปิด Editor หลังสิ้นไตรมาสแล้วกดเพิ่มไตรมาสใหม่ → ไตรมาสเก่าถูกบันทึกเป็นค่าวันนี้) · หน้า PM/Editor บอกให้สร้างไตรมาสใหม่
