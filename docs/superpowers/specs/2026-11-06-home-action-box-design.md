# กล่อง Action ประจำวันบน /home — design (2026-11-06)

## เจตนา

ผู้ใช้เปิด /home ตอนเช้า อยากเห็นทันทีว่า "วันนี้ต้องซื้อหรือขายตัวไหน ตามกฎข้อไหน" ติ๊กได้เลยว่าทำแล้วหรือไม่ทำ แล้วเมื่อเวลาผ่านไปเห็นสรุปว่าการทำหรือไม่ทำตามกฎส่งผลต่อพอร์ตมากน้อยแค่ไหน การ์ด "กฎ 3 ข้อบอกอะไรวันนี้" ปัจจุบันแสดงสถานะของทุกกฎทุกตัวพร้อมกัน ผู้ใช้บอกว่า "มึน" — มันเป็นรายงานสถานะ ไม่ใช่รายการสิ่งที่ต้องทำ

คำพูดผู้ใช้: "เปิด home มาปั๊บ load ข้อมูลล่าสุดปั๊บ เห็นเลยว่าควรต้อง Action อะไร ตามกฎ 1 2 3 บอกแยกกันเลย แล้วติ๊กเลยว่าทำหรือไม่ทำ แล้วเวลาผ่านไปก็มีสรุปว่าที่ทำหรือไม่ทำตามกฎ ส่งผลอะไรกับ port มากน้อยแค่ไหน" · "คงการแจ้งเตือนว่าต้อง action ภายใน 3 วัน ถ้าเกินนั้นก็เอาออกจากกล่องแจ้งเตือนประจำวันไปเลย"

## กฎของผู้ใช้ (คำพูดผู้ใช้ 2026-11-06)

- **กฎ 1** EMA12 ตัดขึ้น EMA26 → ซื้อ · ตัดลง → ขาย
- **กฎ 2** ราคาขึ้นมาเหนือ SMA200 → ซื้อ · ราคาลงมาต่ำกว่า SMA200 → ขาย
- **กฎ 3** ย่อ ≥20% จาก high 1 ปี → ซื้อ (buy the dip)
- universe = BTCUSD + ETHUSD เสมอ + หุ้นธงแดงใน Current Portfolio ของ AI Portfolio Manager (เหมือนการ์ดเดิม)

## เป้าหมาย

1. เปิดหน้ามาแล้วดึงราคาล่าสุดเอง (เหมือนการ์ดเดิม) แล้วเห็น "รายการที่ต้องทำ" ไม่ใช่สถานะ
2. แต่ละรายการ = หุ้น 1 ตัว × กฎ 1 ข้อ × ฝั่ง (ซื้อ/ขาย) × วันที่เกิดสัญญาณ ติ๊กได้ทีละรายการว่า **ทำแล้ว** หรือ **ไม่ทำ**
3. รายการอยู่ในกล่องได้ไม่เกิน 3 วันนับจากวันสัญญาณ เกินแล้วหายจากกล่องและถูกเก็บเป็น "ไม่ได้ตอบ"
4. ทุกการติ๊ก (และทุกรายการที่หมดเวลา) เข้าประวัติ แล้ววัดผลหลังจากนั้นที่ 7 / 30 / 90 วัน
5. มีสรุปว่า ทำตามกฎ / ไม่ทำ / ไม่ได้ตอบ อย่างละกี่ครั้ง ผลเฉลี่ยเท่าไร และผลต่อพอร์ตเป็นบาทเท่าไร แยกตามกฎได้

## ไม่ทำ (non-goals)

- ไม่เปลี่ยนนิยามกฎในเอนจิน (`decision-journal-engine.js` dj-rules-1: แตะ ±3% · ทรงตัว ±2% · ยืนยัน 2 แท่ง · ย่อ 20%) — กล่องนี้เป็นผู้บริโภค `evaluateRules` อีกราย เหมือนการ์ดเดิม
- ไม่ส่งคำสั่งซื้อขายจริง ไม่คำนวณจำนวนหุ้นที่ควรซื้อ ไม่แนะนำว่ากฎไหนถูก
- ไม่ย้าย/ลบหน้า /decision-journal — ใช้ที่เก็บเดียวกันแต่หน้าเดิมยังทำงานเหมือนเดิม
- ไม่แตะ Thai DR / PM / thesis

## สิ่งที่ถือว่าล้มเหลวแม้ "ใช้งานได้" (anti-goals)

- กล่องกลับไปแสดงทุกตัวทุกกฎจนมึนเหมือนเดิม — ต้องแสดงเฉพาะสัญญาณใหม่ใน 3 วัน
- สัญญาณเดียวกันโผล่ซ้ำทุกครั้งที่โหลดหน้า หรือโผล่ใหม่หลังติ๊กไปแล้ว
- ตัวเลขผลลัพธ์ที่ดูดีแต่คำนวณผิดฐาน (เช่น นับ "ไม่ได้ตอบ" เป็นทำแล้ว · ใช้ราคาวันติ๊กแทนราคาวันสัญญาณโดยไม่บอก) — ตามบทเรียน 9arm ของโปรเจกต์
- ตัวเลขเงินบาทโผล่ทั้งที่ Privacy Lock ยังปิดอยู่

## ข้อจำกัดของโปรเจกต์ (ต้องตาม)

- ไฟล์หน้า/เอนจินเป็น ES5 เคร่งครัด (ไม่มี arrow/const/let/template literal) · ข้อความไทยทั้งหมด
- ห้ามคำชี้นำ "ควรซื้อ/ควรขาย/น่าซื้อ/น่าขาย/แนะนำซื้อ/จุดเข้า/ตัดขาดทุน" และ `\b(Buy|Sell)\b` — **ป้าย "ซื้อ" / "ขาย" เฉย ๆ ใช้ได้** เพราะเป็นผลของกฎที่ผู้ใช้ตั้งเอง ไม่ใช่คำแนะนำของระบบ (ต้องมีข้อความกำกับว่า "ตามกฎที่คุณตั้งไว้ ไม่ใช่คำแนะนำการลงทุน")
- เงินบาททุกตัวต้องผ่าน privacy.js (ซ่อนเป็น XXX จนใส่รหัส) และห้ามใส่จำนวนเงินใน `title`
- ห้าม commit จนผู้ใช้สั่ง "push git" · เขียนสคริปต์ด้วย Write tool (ไม่ใช้ heredoc/`node -e` ที่มี regex)
- เทสต์: VM harness แบบ `scripts/home-rules-test.js` + mutation test + ตรวจหน้าจริงใน Chrome (CDP probe ดัก /api/portfolio-holdings ด้วยข้อมูลสมมุติ ห้ามแตะรหัสผ่าน) ทั้ง 1440 และ 390 px · ทั้งเว็บต้อง 41/41 ชุด

## สิ่งที่ผู้ใช้ตัดสินแล้ว

- รูปแบบ **B: การ์ดต่อหุ้น** (เลือกจาก mockup 2026-11-06) — หุ้นละการ์ด เฉพาะหุ้นที่มีสัญญาณใหม่ใน 3 วัน ในการ์ดมี 3 บรรทัดกฎ 1-2-3 เสมอ บรรทัดที่มีสัญญาณขึ้นป้าย ซื้อ/ขาย + เหตุผลสั้น + วันที่สัญญาณ + ปุ่ม ทำแล้ว / ไม่ทำ · บรรทัดที่ไม่มีสัญญาณบอกว่า "ไม่มีสัญญาณใหม่" (พร้อมสถานะสั้น ๆ เช่น "ย่อ −12.8% ยังไม่ถึง 20%")
- ถ้ากฎขัดกันในหุ้นเดียว (เช่น DDOG กฎ 1+2 ขาย แต่กฎ 3 ซื้อ) แสดงทั้งหมด ผู้ใช้ตัดสินเอง
- ติ๊กแล้วบรรทัดยังอยู่แบบจาง (มี ✓ และปุ่ม "แก้") จนครบ 3 วันค่อยหาย
- ประวัติ + สรุปอยู่ใต้กล่องบน /home แบบพับได้ และรายการทั้งหมดไปอยู่ใน Decision Journal
- หน่วยผล: % ราคาที่ขยับหลังสัญญาณ และ "ผลต่อพอร์ต" เป็นบาท

## การตัดสินใจของผู้ออกแบบ (ผู้ใช้ยังไม่ได้ยืนยันทีละข้อ — เปลี่ยนได้)

1. **สัญญาณ = เหตุการณ์ ไม่ใช่สถานะ** และ **วันสัญญาณ D = วันที่ของ "แท่งที่สัญญาณกลายเป็นของจริง"** (แท่งที่ปิดตลาดแล้วตามกติกา closedBarCutoff ของเอนจิน) — ราคาปิดของแท่งนั้นคือฐานวัดผล:
   - กฎ 1: แท่งที่ EMA12 ตัด EMA26 (`r1.crossDir`, `r1.crossBarsAgo` ของ `evaluateRules`)
   - กฎ 2: **แท่งยืนยัน** (แท่งที่สองหลังราคาปิดข้าม SMA200 ตาม CONFIRM_BARS ของเอนจิน) — ไม่ใช่แท่งที่ข้าม เพราะก่อนยืนยันผู้ใช้ยังไม่เห็นสัญญาณ ถ้านับจากแท่งข้ามหน้าต่าง 3 วันจะหมดก่อนได้เห็น · ข้อความบอกทั้งสองวัน ("ข้าม SMA200 เมื่อ 03 พ.ย. · ยืนยัน 04 พ.ย.") · ยืนยัน 2 แท่งคือกันสัญญาณหลอก ไม่ใช่กฎใหม่
   - "แตะเส้นแล้วเด้ง" (`touchBounce`: ราคาลงมาแตะหรือเข้าใกล้ SMA200 ±3% แล้วเด้งขึ้นโดยไม่หลุด) **นับเป็นสัญญาณซื้อของกฎ 2 ด้วย** (ผู้ใช้ยืนยัน 2026-11-06) · วันสัญญาณ D = แท่งแรกที่ `touchBounce.met` กลายเป็นจริงในรอบนั้น (ไล่ทีละแท่ง) ข้อความบอกวันแตะ (`touchDate`) ด้วย · หนึ่งรอบแตะมีสัญญาณครั้งเดียว · ดังนั้นฝั่งซื้อกฎ 2 = `r2.buy` ของเอนจิน (ข้ามขึ้นยืนยัน หรือ เด้ง) · ฝั่งขายกฎ 2 = `r2.sell` (หลุดลงยืนยัน)
   - กฎ 3: **แท่งแรก**ที่ย่อถึง 20% จาก high 1 ปี ในรอบย่อปัจจุบัน — เอนจินต้องเพิ่ม `r3.dipSinceDate` โดยไม่เปลี่ยน `dipMet/buy` เดิม · **รอบย่อ** เริ่มเมื่อราคาย่อถึง 20% และจบเมื่อ drawdown จาก high 1 ปี (rolling 252 แท่ง) **ฟื้นดีกว่า −10%** (hysteresis กันสัญญาณซ้ำตอนราคาแกว่งแถว −20%) · high ที่หลุดหน้าต่าง 252 แท่งไปเองจนตัวเลข drawdown เปลี่ยน **ไม่** เริ่มรอบใหม่ · หนึ่งรอบมีสัญญาณซื้อได้ครั้งเดียว
   - ฝั่งซื้อของกฎ 3 แสดงเป็นข้อเท็จจริง "ย่อถึง 20%" เหมือนการ์ดเดิม (ไม่ต้องติ๊ก conviction)
2. **หน้าต่าง 3 วัน = วันปฏิทินเวลากรุงเทพ หลังแท่ง D ปิด** รายการมองเห็นได้ตั้งแต่แท่ง D ปิดตลาด (หุ้นสหรัฐ = เช้าวัน D+1 ไทย) ถึงสิ้นวัน **D+3** → เห็นได้ 3 วันเต็มเสมอ (สัญญาณแท่งศุกร์ของหุ้นสหรัฐ เห็น เสาร์-อาทิตย์-จันทร์) · บอก "เหลือ N วัน" / "วันสุดท้าย" · พ้นแล้วรายการที่ยังไม่ติ๊กถูกบันทึกอัตโนมัติเป็น **ไม่ได้ตอบ** (นับเป็นไม่ทำในสรุป แต่แยกป้ายให้เห็น) ทำครั้งเดียวต่อรายการ (idempotent) ตอนโหลดหน้าครั้งถัดไป · **ไม่ได้ตอบครอบคลุมทุกเหตุการณ์ที่หมดเวลาโดยไม่ติ๊ก ไม่ว่าผู้ใช้จะเปิดหน้าทันไหม** (กฎทำงาน ผู้ใช้ไม่ได้ทำ = ไม่ได้ทำ ตามเจตนา "ผลของการไม่ทำตามกฎ") **ยกเว้น**เหตุการณ์ที่หมดหน้าต่างไปแล้วก่อนวันเริ่มใช้งาน (D + 3 < `launchedAt` · `launchedAt` เก็บใน localStorage ทันทีที่กำหนด และในเอกสารเมื่อบันทึกครั้งแรก) ซึ่งไม่บันทึกและไม่แสดงเลย — เหตุการณ์ที่ยังอยู่ในหน้าต่างวันเปิดใช้ครั้งแรกจะแสดงตามปกติ (ปรับถ้อยคำ 2026-11-06 ระหว่างสร้าง: เดิมเขียนว่า "D ก่อนวันเริ่มใช้งาน" ซึ่งทำให้วันแรกไม่เห็นอะไรเลย)
3. **เอกลักษณ์รายการ** = `symbol|rule|side|signalDate` · **การหาเหตุการณ์ต้องไล่ทีละแท่ง** ย้อนหลังอย่างน้อย 30 วันปฏิทินจากแท่งปิดล่าสุด (ไม่ใช่อ่านแค่สถานะล่าสุดของ `evaluateRules` ซึ่งให้เฉพาะการตัดครั้งหลังสุด) เพื่อให้สัญญาณที่กลับทิศในหน้าต่างหรือเกิดตอนผู้ใช้ไม่ได้เปิดหน้า ยังถูกบันทึกเป็น ไม่ได้ตอบ · ผลไล่เทียบกับประวัติ (รวม tombstone ที่ลบจาก /decision-journal = "ไม่ต้องบันทึกซ้ำ"): มีแล้ว → ไม่สร้างซ้ำ · ยังไม่มีและอยู่ในหน้าต่าง → แสดง · ยังไม่มีและพ้นหน้าต่าง → บันทึกเป็น ไม่ได้ตอบ · การ์ดเดิม "กฎ 3 ข้อบอกอะไรวันนี้" ถูกแทนที่ด้วยกล่องนี้ (ไม่มีสองการ์ด)
4. **ที่เก็บ = เอกสาร Decision Journal เดิม** (`/api/portfolio?doc=journal` + ร่าง localStorage + `mergeDocs` updatedAt ใหม่ชนะ) — ทุกการติ๊กสร้าง entry ที่มี `source: "home-action"`, `symbol`, `date` = วันสัญญาณ D, `action.kind` = buy/sell (= ฝั่งที่กฎบอก ไม่ใช่สิ่งที่ผู้ใช้ทำ), `rules.asOfBar` + `rules.close` = ราคาปิดแท่ง D (ฐานวัดผล), `ruleNo` 1/2/3, `response` = `done` | `skipped` | `unanswered`, `respondedAt`, `execPrice` (ราคาที่ทำจริง ค่าเริ่มต้น = ราคาปิดล่าสุด แก้ได้ · ใช้เฉพาะแสดง ไม่ใช่ฐานวัดผล), `positionValue` (มูลค่าที่ถือ ณ ตอนติ๊ก จาก holdings — ฝั่งขาย), `amount` (เงินที่ซื้อ ฝั่งซื้อ ใส่หรือไม่ก็ได้) · **ไม่มี `verdict` และไม่มี `view.horizonDays`** · **สถิติ/ทบทวนของ /decision-journal เดิมต้องกรอง `source === "home-action"` ออก** (ไม่งั้น "ไม่ทำ" จะถูกนับเป็นการขายที่ทำตามกฎ) · หน้า /decision-journal แสดง entry พวกนี้ในรายการพร้อมป้าย "จากกล่อง Action · กฎ N · ทำแล้ว/ไม่ทำ/ไม่ได้ตอบ" และ**ลบได้อย่างเดียว** (ไม่เพิ่ม UI แก้ไขที่นั่น) · การแก้ response/ราคา/จำนวนเงินทำที่กล่องบน /home (ปุ่ม "แก้" ในหน้าต่าง 3 วัน และในตารางประวัติ) · entry ที่ถูกลบ (tombstone) = ผู้ใช้ไม่ต้องการรายการนั้น → กล่องไม่บันทึกซ้ำเป็น ไม่ได้ตอบ
5. **วัดผล** ใช้ `outcomes(entry, bars, nowBangkok)` เดิม (ฐาน = ราคาปิดวันสัญญาณ, ช่วง 7/30/90 วัน, นับเฉพาะแท่งที่ปิดแล้ว) · ทิศทาง: ขาย → ราคาลง = ดี (เลี่ยงได้) · ซื้อ → ราคาขึ้น = ดี · สำหรับ `skipped`/`unanswered` ตัวเลขเดียวกันอ่านว่า "ถ้าทำจะได้/พลาด"
6. **ผลต่อพอร์ต (บาท)** = % ที่ราคาขยับในช่วงที่เลือก × `positionValue` (ฝั่งขาย) หรือ × `amount` (ฝั่งซื้อ ถ้าใส่) · ไม่มีฐานเงิน (ETH ไม่ได้ถือ, ซื้อไม่ใส่จำนวน) → แสดง % อย่างเดียวและบอกว่า "ไม่มีฐานเงิน" · ค่าเงินต่างประเทศแปลงเป็นบาทด้วยค่าที่ holdings ใช้ตอน snapshot (ถ้าไม่มี → แสดงสกุลเดิม) · ทุกตัวเลขบาทผ่าน privacy.js
7. **สรุป** สองแกนแยกกัน: (ก) **ช่วงสัญญาณ** = สัญญาณใน 90 วันหลังสุด (ตายตัว) (ข) **ช่วงวัดผล** = ปุ่มสลับ **7 วัน (ค่าเริ่มต้น) / 30 วัน** — ตัวเลขใน 4 ช่องและคอลัมน์ "ผลต่อพอร์ต" ใช้ช่วงวัดผลที่เลือก (ค่าเริ่มต้น 7 วันเพื่อให้รายการส่วนใหญ่มีผลให้ดู ไม่ใช่ "รอ" เกือบทั้งหมด) · 4 ช่อง: ทำตามกฎ (ครั้ง · %เฉลี่ย · ฿รวม) · ไม่ทำ (ครั้ง · ถ้าทำจะได้ %เฉลี่ย · ฿ที่พลาด) · ไม่ได้ตอบ (ครั้ง) · แยกตามกฎ (ค่าเฉลี่ยต่อครั้งที่ช่วงวัดผลที่เลือก) · รายการที่ยังไม่ครบช่วงแสดง "รอ (n/7)" และไม่นับในค่าเฉลี่ย · ตารางประวัติมีทั้งคอลัมน์ 7 และ 30 วัน เรียงใหม่→เก่า
8. **ราคา** ใช้เส้นทางเดียวกับการ์ดเดิม (`/api/ohlc` ตรง + cache `home_rules_ohlc_v1` + `barsInflight`) ไม่ยิงซ้ำ · entry ที่ต้องวัดผลแต่ไม่อยู่ใน universe ปัจจุบัน (เช่น หุ้นที่ขายออกไปแล้ว) ยังต้องดึงราคามาวัดได้
9. **mount** เหมือนการ์ดเดิม (ลูกคนแรกของ `#mcRoot` + MutationObserver รอดการวาดทับ) · CSS ใช้ token ของ mission-control-v2.css ต่อจาก `.hr-*` (เปลี่ยนเป็น prefix ใหม่ได้)
10. ข้อความกำกับใต้หัวกล่อง: "ตามกฎที่คุณตั้งไว้ (EMA12/26 · SMA200 · ย่อ ≥20%) ไม่ใช่คำแนะนำการลงทุน · แสดงเฉพาะสัญญาณใน 3 วันหลังสุด"
