# Decision Journal: คำตอบจากกล่อง Action เป็น "สิ่งที่ทำจริง" + สรุปผลทำ/ไม่ทำ 3 ช่วง

วันที่ 2026-11-19 · ขนาด: แก้เล็ก (short design)

## เจตนา
ผู้ใช้อยากรู้ว่า "ทำตามกฎแล้วคุ้มไหม" — กล่อง "ต้องทำอะไรวันนี้" บน /home ส่งคำตอบ (ทำแล้ว / ไม่ทำ / ไม่ได้ตอบ) เข้า Decision Journal อยู่แล้ว (`source: "home-action"`) แต่:
- ช่อง "ทำอะไร" ของรายการเหล่านี้แสดงฝั่งของกฎเสมอ (ซื้อ/ขาย) แม้ตอบ "ไม่ทำ" → อ่านแล้วเหมือนได้ทำไปแล้ว
- หน้า Journal ไม่สรุปผลของรายการจากกล่องเลย (ถูกกรองออกจากสถิติ) · สรุปทำ/ไม่ทำมีแค่บนกล่อง Home ที่ 1 สัปดาห์ / 1 เดือน

## เป้าหมาย
1. ช่อง "ทำอะไร" ของรายการจากกล่อง = สิ่งที่ผู้ใช้ทำจริงตามคำตอบ
2. หน้า Journal มีการ์ดสรุป "ทำแล้ว" เทียบ "ไม่ทำ / ไม่ได้ตอบ (ถ้าทำจะได้)" ที่ **1 สัปดาห์ / 1 เดือน / 3 เดือน** (ระยะสั้น/กลาง/ยาว — ผู้ใช้เลือก ก.)

## ไม่ทำ (non-goals)
- ไม่แก้ข้อมูลที่บันทึกไว้ ไม่ย้าย/เขียนรายการเก่า ไม่เปลี่ยนสูตร id `ha_<SYM>_<rule>_<side>_<date>`
- ไม่เปลี่ยนตัวเลือกช่วงบนกล่อง Home (ยัง 1 สัปดาห์ / 1 เดือน)
- ไม่เอารายการจากกล่องเข้าสถิติเดิม ("ตามกฎ" · "คาดถูก" · ตารางสถิติ) — นั่นคือคำทำนายของบันทึกที่เขียนเอง
- ไม่ดึงราคาเพิ่ม — ใช้ `state.outcomesById` ที่หน้า Journal คิดอยู่แล้ว (DecisionJournal.outcomes มีช่วง 7/30/90)

## ห้ามเกิด (anti-goals)
- ช่วงเดียวกัน (1 สัปดาห์ / 1 เดือน) กับชุดรายการเดียวกัน ได้ตัวเลขไม่ตรงกับกล่อง Home
- เงินโผล่ตอนล็อก Privacy หรืออยู่ใน title/aria-label
- ค่าเฉลี่ยที่คิดจากบางรายการ แต่อ่านเหมือนครอบทุกรายการ (ต้องบอก n ที่ครบกำหนด และ "จาก n รายการที่มีฐานเงิน" เมื่อเงินรวมมาจากบางแถว)

## ทางที่พิจารณา
**ส่วนที่ 1 — ช่อง "ทำอะไร"**
- **ก. แก้ตอนแสดงผล (ผู้ใช้เลือก)** — ข้อมูลที่เก็บไม่เปลี่ยน · หน้า Journal คิด "สิ่งที่ทำจริง" จาก `ha.response` + `ha.side` ผ่าน helper ตัวเดียว · รายการเก่าถูกทันทีโดยไม่ PUT
- ข. แก้ข้อมูลที่บันทึก + ย้ายรายการเก่า — ตัดทิ้ง: การย้ายทำให้ `updatedAt` ใหม่ขึ้นแล้วชนะ merge ทับคำตอบจริงจากอีกเครื่อง (ระบบตั้งใจประทับ "ไม่ได้ตอบ" ที่เที่ยงคืนวันสัญญาณเพื่อกันเรื่องนี้) และ `sideOf()`/`outcomes()` อ่านช่องที่เก็บอยู่

**ส่วนที่ 2 — สรุปผล**
- **ใช้ `HomeActionEngine.summary()` ตัวเดียวกับกล่อง Home (ทางเดียวที่สมเหตุสมผล)** — ขยายให้รับช่วง 90 วัน · ตัวเลขสองหน้าจึงมาจากสูตรเดียว
- เขียนสูตรใหม่ใน Journal — ตัดทิ้ง: สองทางเดินข้อมูล วันหนึ่งเลขไม่ตรงกัน

## สิ่งที่ตัดสินแล้ว
- **สิ่งที่ทำจริง** (เฉพาะ `source === "home-action"`):
  - `done` → ฝั่งของกฎ (`ha.side`: ซื้อ / ขาย)
  - `skipped` หรือ `unanswered` + ฝั่งซื้อ → `none` "ไม่ทำอะไร"
  - `skipped` หรือ `unanswered` + ฝั่งขาย → `hold` "ถือต่อ"
  - ไม่รู้คำตอบ/ไม่รู้ฝั่ง → ค่าที่เก็บเดิม (`action.kind`)
  - ใช้ค่านี้ทุกจุดที่แสดงหรือกรอง "ทำอะไร": แถวในบันทึกทั้งหมด · การ์ดรายละเอียด · ตัวกรอง "ทำอะไร" · ช่องค้นหา · รายการเลือกบันทึกในฟอร์มไม้จริง · บรรทัดผลการกระทำ (ถ้ามี) — ชิป "จากกล่อง Action · กฎ n · คำตอบ" คงเดิม
  - บันทึกที่เขียนเองไม่เปลี่ยน
- **การ์ดสรุป** "ผลของการทำตามกฎ (จากกล่อง Action)":
  - วางในคอลัมน์ขวาต่อจาก "สถิติ"
  - 2 แถว: "ทำแล้ว" (followed) · "ไม่ทำ / ไม่ได้ตอบ (ถ้าทำจะได้)" (missed) — กลุ่มเดียวกับ summary() ของกล่อง
  - 3 คอลัมน์: 1 สัปดาห์ / 1 เดือน / 3 เดือน · ช่อง = ผลต่อพอร์ตเฉลี่ย % (ลงสีบวก/ลบ) + "n รายการ" · ยังไม่ครบกำหนดเลย = "รอผล"
  - บรรทัดล่าง: จำนวนที่รอผล · เงินรวมแยกสกุลของช่วงที่ยาวที่สุดที่มีผล (หรือทุกช่วง — ผู้สร้างเลือก) พร้อม "จาก n รายการที่มีฐานเงิน" เมื่อไม่ครบ · คำอธิบายสั้นว่า "ถ้าทำจะได้" อ่านอย่างไร
  - ยังไม่มีรายการจากกล่อง / โหลดเอกสารไม่ได้ / กำลังดึงราคา → ข้อความแทน (ตามแบบ placeholder เดิมของหน้า)
- **เอนจิน:** `summary()` รับ `horizonDays` ที่อยู่ใน `DecisionJournal.HORIZONS` (7/30/90) · `HomeActionEngine.HORIZONS` ที่กล่อง Home ใช้ทำปุ่มสลับยังเป็น [7, 30] · rows/สิ่งที่กล่อง Home ใช้อยู่ต้องได้ค่าเท่าเดิมทุกไบต์
- **ชุดรายการของการ์ด Journal = ทุกรายการจากกล่องในเอกสาร (ไม่จำกัด 90 วัน)** — ผู้ช่วยตัดสินตอนวางแผน (2026-11-19): สรุปบน Home นับเฉพาะสัญญาณ `SUMMARY_DAYS` = 90 วันหลังสุด ถ้าการ์ดใช้กรอบเดียวกัน ช่อง 3 เดือนจะแทบไม่มีรายการที่ครบกำหนด · `summary()` จึงรับ `allTime: true` · การ์ดเขียนชัดว่า "ทุกสัญญาณที่บันทึกไว้" · ตอนนี้ (กล่องเริ่มใช้ 6 พ.ย. 2026) ทุกรายการอยู่ใน 90 วัน ตัวเลข 1 สัปดาห์/1 เดือนจึงเท่ากับบน Home · ตั้งแต่ราว ก.พ. 2027 อาจต่างได้เพราะคนละชุด (Home = 90 วันหลังสุด) ไม่ใช่สูตรต่าง
- หน้า Journal โหลด `home-action-engine.js` เพิ่ม (pure · ไม่แตะราคา)

## Addendum A (2026-11-19): รายการรายตัวในการ์ด
ผู้ใช้: "อยากเห็นรายตัวด้วย" ว่าสิ่งที่กล่อง Home บอก → เราตัดสินใจอย่างไร → เกิดอะไรขึ้น · เลือก **ข. ตัวเลข + ประโยคสรุป** · อนุมัติทาง "ใต้ตารางในการ์ดเดิม" (ทางอื่นตัดทิ้ง: เติมในแถว "บันทึกทั้งหมด" = ยังปนบันทึกมือและต้องกางทีละแถว · ส่วนใหม่แยก = ภาพรวมกับรายตัวแยกกัน)

- **ที่อยู่:** ใต้ตารางสรุปในการ์ด `djHaOut` · หัวย่อย `รายตัว (ใหม่สุดก่อน)`
- **ชุดรายการ:** แถวเดียวกับที่สรุปนับ (`summary(…, { allTime: true }).rows` — ไม่รวมที่ถูกลบ) เรียงใหม่→เก่า · แสดง 10 รายการล่าสุด + ปุ่ม `ดูทั้งหมด (n)` / `ย่อ` (จำในหน่วยความจำของหน้าเท่านั้น)
- **แต่ละรายการ:**
  - บรรทัด 1: วันที่ · สัญลักษณ์ · ชื่อกฎ (`HomeActionEngine.RULE_LABEL`) · `ระบบบอก: ซื้อ|ขาย` + ชื่อเหตุการณ์ (`HomeActionEngine.kindThai`)
  - บรรทัด 2: `คุณ: ทำแล้ว (ขาย ที่ <ราคา>)` · `คุณ: ไม่ทำ (ถือต่อ)` · `คุณ: ไม่ได้ตอบ (ไม่ทำอะไร)` — สิ่งที่ทำจริงจาก `actionKindOf` · ราคาที่ทำจริงเป็นราคาตลาดต่อหน่วย (ไม่ซ่อน)
  - ตารางเล็ก 3 ช่อง 1 สัปดาห์ / 1 เดือน / 3 เดือน: ป้ายแถว `ได้/เสีย` (ทำแล้ว) หรือ `ถ้าทำจะได้` (ไม่ทำ/ไม่ได้ตอบ) · ค่า = ผลต่อพอร์ต % (`HomeActionEngine.impactPct(entry, ราคาขยับของช่วงนั้น)`) ลงสีตามเครื่องหมายแม้ล็อก · ยังไม่ครบ = `รอผล` · ไม่มีราคา = `—`
  - **ประโยคสรุป** จากช่วงยาวที่สุดที่มีผลแล้ว (3 เดือน > 1 เดือน > 1 สัปดาห์) · ใช้เกณฑ์ทรงตัวของ Journal (`FLAT_BAND_PCT` = ±2%):
    - |ผล| ≤ 2%: `ราคาแทบไม่ขยับ (±2%) ใน <ช่วง> — ทำหรือไม่ทำผลใกล้กัน`
    - ทำแล้ว · ผล > 2%: `ทำแล้วได้ +x% ใน <ช่วง>` · ผล < −2%: `ทำแล้วเสีย −x% ใน <ช่วง>`
    - ไม่ทำ/ไม่ได้ตอบ · ผล > 2%: `<ไม่ทำ|ไม่ได้ตอบ>แล้วพลาด: ถ้าทำจะได้ +x% ใน <ช่วง>` · ผล < −2%: `<ไม่ทำ|ไม่ได้ตอบ>แล้วดี: ถ้าทำจะเสีย −x% ใน <ช่วง>`
    - ต่อท้ายด้วยราคาขยับจริง `(ราคาขึ้น|ลง y%)` และเงินเมื่อมีฐาน ` · ≈ <moneySigned(…, true)>` (ล็อก = XXX)
    - ยังไม่มีช่วงไหนครบ: `ยังไม่ครบ 1 สัปดาห์ — รอผล` · ดึงราคาไม่สำเร็จ: `ดึงราคาไม่สำเร็จ — ยังไม่รู้ผล`
- **ต้องตรงกัน:** ค่าเฉลี่ยผลของรายการที่มีผลแล้วในแต่ละกลุ่ม/ช่วง = ตัวเลขในตารางสรุปเดียวกัน (คิดจากสูตรเดียวกัน)
- **ไม่ทำ:** ไม่แก้ข้อมูลที่เก็บ · ไม่ดึงราคาเพิ่ม · ไม่ใส่ลิงก์/ปุ่มอื่นในรายการ · เวอร์ชันยังเป็น dj-7 (ยังไม่เคยขึ้นจริง · เซิร์ฟเวอร์ส่ง no-cache)
