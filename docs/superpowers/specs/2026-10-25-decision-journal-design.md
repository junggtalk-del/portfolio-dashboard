# Decision Journal — บันทึกการตัดสินใจลงทุน (`/decision-journal`)

วันที่ 2026-10-25 · สถานะ: ผู้ใช้อนุมัติกติกา 3 ข้อและให้เริ่มสร้าง · ยังไม่ commit จนกว่าผู้ใช้สั่ง "put git"

## 1. เจตนา และทำไมต้องมี

ผู้ใช้ขายหุ้นเพราะข่าวร้าย + บรรยากาศตลาดแย่ + ราคาลงมาแล้ว โดยคาดว่าจะลงต่อแล้วค่อยซื้อกลับถูกกว่า เกิดขึ้น 2 ครั้ง ทั้งสองครั้งราคาเด้งหลังขาย ต้องซื้อกลับแพงกว่าเดิม ต้นทุนเพิ่ม

สองครั้งอาจเป็นเรื่องบังเอิญ สิบครั้งคือนิสัย หน้านี้มีไว้เก็บหลักฐานให้ครบพอจะเห็นนิสัยของตัวเอง:

1. **ตอนตัดสินใจ** — เห็นอะไร รู้สึกยังไง คาดว่าจะเกิดอะไร ทำอะไร และ **กฎที่ตั้งไว้บอกว่าอะไร** (ระบบตอบเอง แก้ไม่ได้)
2. **ตอนย้อนกลับมาดู** — เกิดอะไรขึ้นจริง ตัดสินใจถูกหรือผิด ทำตามกฎหรืออารมณ์พาไป ได้บทเรียนอะไร
3. **ไม้จริง** — ทุกครั้งที่ซื้อ/ขายจริง กำไรหรือขาดทุนกี่บาท/ดอลลาร์ และเคส "ขายแล้วซื้อกลับแพงกว่า" ต้องเห็นเป็นตัวเลขทันที

หลักการเดียวที่ห้ามละเมิด (เหมือน `btc-forecast-log.js`): **สิ่งที่บันทึก ณ ตอนนั้น ต้องแช่แข็ง** ความคิด/อารมณ์/คาดการณ์/สิ่งที่กฎบอก เขียนทับไม่ได้ เพราะพอรู้ผลแล้วความจำจะแต่งเรื่องเอง ส่วน "ผลจริง" ต้องมาจากราคาจริงเท่านั้น ห้ามเดา

## 2. เป้าหมาย / ไม่ทำ / ถ้าเป็นแบบนี้ถือว่าล้มเหลว

**เป้าหมาย**
- บันทึก 1 รายการได้ใน ~1 นาที จากมือถือก็ได้ (คนบันทึกตอนอารมณ์กำลังมา ไม่ใช่ตอนว่าง)
- ตอนกดบันทึก ระบบตอบทันทีว่า "กฎทั้ง 3 ข้อบอกว่าอะไร" และสรุปว่า **ตามกฎ / แหกกฎ** สำหรับสิ่งที่ทำ
- เมื่อถึงกำหนด (1 สัปดาห์ / 1 เดือน / 3 เดือน) ระบบเติมราคาจริงให้ และชี้ว่าคาดถูกหรือผิด ผู้ใช้แค่เขียนบทเรียน
- เห็นภาพรวม: ครั้งที่ทำตามกฎ vs แหกกฎ ผลต่างกันแค่ไหน · อารมณ์แบบไหนพาไปผิดบ่อย
- ไม้จริง: กำไร/ขาดทุนต่อไม้ (ขายจับคู่ซื้อ) และไม้ที่ยังเปิดอยู่

**ไม่ทำ (V1)**
- ไม่ให้คำแนะนำซื้อ/ขาย ไม่มีคะแนนความน่าสนใจ ไม่มี alert
- ไม่แปลงสกุลเงิน (กำไร/ขาดทุนแสดงในสกุลของหลักทรัพย์นั้น)
- ไม่ดึงไม้จริงจากโบรกเกอร์ · ไม่เชื่อม Quarterly Editor
- ไม่สร้าง "ระบบบอกว่า" จาก Action Center (สัญญาณของเว็บคำนวณต่างกันหลายที่ — ใช้เฉพาะกฎ 3 ข้อของผู้ใช้)

**ล้มเหลวแม้โค้ดจะทำงาน ถ้า**
- บันทึกเก่าเปลี่ยนตัวเลขเมื่อเปิดหน้าใหม่ (track record ไร้ความหมาย)
- "ตามกฎ/แหกกฎ" ติ๊กเองได้ หรือคำนวณจากราคาผิดวัน (ใช้แท่งที่ยังไม่ปิดตลาด)
- แท็บ Quarterly Editor ที่เปิดค้างเขียนทับบันทึก (บั๊กที่เจอแล้วใน `app.js`)
- ใช้คำโฆษณา (ควรซื้อ/ควรขาย/จุดเข้า) หรือซ่อนว่าข้อมูลไม่พอแล้วโชว์ตัวเลขสวย ๆ

## 3. กติกา 3 ข้อ — นิยามที่ผู้ใช้อนุมัติ (2026-10-25)

ทุกข้อคิดจาก **ราคาปิดรายวันของแท่งที่ปิดตลาดแล้ว** เท่านั้น ("แท่ง as-of" ดู §5.2) ค่าดิบไม่ปัด ปัดเฉพาะตอนแสดงผล

| กฎ | นิยามที่ใช้ |
|---|---|
| **1 EMA12/26** | `state = ema12 > ema26 ? bull : (< ? bear : flat)` บนแท่ง as-of · ซื้อ "เข้ากฎ" เมื่อ bull · ขายเข้ากฎเมื่อ bear · บอกด้วยว่าตัดครั้งล่าสุดเมื่อกี่แท่ง (`crossBarsAgo` 0 = ตัดบนแท่ง as-of) ทิศไหน · **ไม่จำกัดว่าต้องซื้อ/ขายวันที่ตัด** |
| **2 หลุด SMA200** | ขายเข้ากฎเมื่อ `close < sma200` ติดต่อกัน **≥ 2 แท่ง** (นับรวมแท่ง as-of) · ต่ำวันเดียวยังไม่นับ |
| **2 ยืนได้** | ซื้อเข้ากฎเมื่อ `close > sma200` ติดต่อกัน ≥ 2 แท่ง **และ** จุดตัดขึ้นครั้งล่าสุดอยู่ไม่เกิน 10 แท่งก่อนหน้า (`crossBarsAgo ≤ 9`, ทิศ up) |
| **2 แตะแล้วเด้ง** | (ผู้ใช้ยืนยัน 2026-10-26: "แตะแล้วเด้ง หรือเข้าไปใกล้ ๆ แล้วเด้ง ใช้ได้หมด 3%") ครบทั้ง 3 ข้อ: **(ก)** มีแท่ง `t` ใน 5 แท่งก่อนแท่ง as-of (`asOf−5 … asOf−1`) ที่ `sma200[t] × 0.97 ≤ low[t] ≤ sma200[t] × 1.03` — ลงไปแตะ/ทะลุเส้นไม่เกิน 3% หรือเข้าใกล้จากด้านบนในระยะ 3% โดยไม่แตะก็นับ (แท่งที่ไม่มี low ใช้ close) **(ข)** ก่อนแท่ง as-of ราคา**ไม่ได้อยู่ในภาวะหลุดยืนยัน** คือจำนวนแท่งปิดใต้ SMA200 ติดต่อกันที่จบที่ `asOf−1` น้อยกว่า 2 (ถ้า ≥ 2 = หลุดยืนยันแล้ว การกลับขึ้นต้องผ่านกฎ "ยืนได้" 2 วัน ไม่ใช่ "เด้ง") **(ค)** แท่ง as-of `close > sma200` และ `close > close[t]` · ใช้ `low` จาก `/api/ohlc` (snapshot ของเว็บไม่มี low จึงต้องใช้ ohlc) |
| **3 ย่อ 20%** | `high1y = max(close ของ 252 แท่งล่าสุดรวม as-of)` · `dd1yPct = (close / high1y − 1) × 100` (ค่าลบ ไม่ปัด) · `dipMet = dd1yPct ≤ −20` · ซื้อเข้ากฎเมื่อ `dipMet && conviction` โดย `conviction` คือช่องติ๊ก "ศึกษามาดี/มั่นใจ" ที่ผู้ใช้ติ๊กเอง (ระบบตัดสินไม่ได้) · ข้อนี้ไม่เกี่ยวกับการขาย |

การตัด (cross) ทั้ง EMA และ SMA200 ใช้นิยามเดียวกับ `data-snapshot.js crossDays/smaReclaimDays`: ขึ้น = `prev ≤ && now >` · ลง = `prev ≥ && now <` · **ไม่มีตัวกรอง anti-glitch** ของ Action Center (หน้านี้ตัดสินจาก "สภาพ" ไม่ใช่ "ความสด") ระบุไว้ในบันทึกว่าใช้ `rulesVersion: "dj-rules-1"`

ข้อมูลไม่พอ: EMA ต้องมี ≥ 26 แท่ง · SMA200 ต้องมี ≥ 200 แท่ง · high1y ถ้ามีน้อยกว่า 252 แท่งให้ใช้เท่าที่มีและบันทึก `high1yWindowBars` — ค่าที่คิดไม่ได้เป็น `null` และกฎข้อนั้นมีสถานะ `na` ห้ามเป็น 0

ขอบเขตตัวเลข: การเทียบเกณฑ์ที่เป็นเปอร์เซ็นต์ (`dd1yPct ≤ −20`, แถบทรงตัว `|pct| ≤ 2`, แถบแตะ ±3%, ฐานราคาเปลี่ยน `> 0.5%`) ใช้ความคลาดเคลื่อน `EPS_PCT = 1e-9` เข้าข้างเกณฑ์ เพื่อให้ราคา 2 ตำแหน่งที่ย่อ −20.0% พอดี (เช่น 100.05 → 80.04 ซึ่งคำนวณได้ −19.999999999999993) นับว่าเข้าเกณฑ์ ตรงกับตัวเลขที่จอแสดง · ข้อความว่าง/ช่องว่าง (`" "`) ไม่ใช่ตัวเลข = `null` ไม่ใช่ 0 · low ที่ ≤ 0 ถือว่าไม่มี ใช้ close แทน

## 4. คำตัดสิน "ตามกฎ / แหกกฎ" (คำนวณตอนบันทึก แล้วแช่แข็ง)

```
r1.buy = state==='bull'      r1.sell = state==='bear'
r2.sell = state==='below' && consecutive>=2
r2.buy  = reclaimHeld || touchBounce.met
r3.buy  = dipMet && conviction
```

| action | supports | opposes | compliance |
|---|---|---|---|
| buy | r1.buy, r2.buy, r3.buy | r1.sell, r2.sell | `supports.length>0 ? 'per-rule' : 'against'` |
| sell | r1.sell, r2.sell | r1.buy, r2.buy | เหมือนกัน |
| hold / none | — | — | `'n/a'` แต่บันทึก `rulesSay` ไว้ให้ดูย้อนหลัง |

- `rulesSay` (ทุก action): `'buy'` ถ้ามีกฎสนับสนุนซื้อและไม่มีกฎสนับสนุนขาย · `'sell'` กลับกัน · `'mixed'` ถ้ามีทั้งคู่ · `'none'` ถ้าไม่มีเลย
- ถ้ากฎ 1 และ 2 เป็น `na` ทั้งคู่ (ข้อมูลไม่พอ) → `compliance: 'unknown'` และหน้าเว็บบอกว่า "ข้อมูลราคาไม่พอตัดสิน"
- เคสของผู้ใช้ (ขายเพราะข่าวร้าย ขณะ EMA bull และราคาเหนือ SMA200) → supports ว่าง, opposes = [r1] → **แหกกฎ** พร้อมเหตุผล "กฎ 1: EMA12 ยังเหนือ EMA26 · กฎ 2: ยังไม่หลุด SMA200"

## 5. ข้อมูลและการคำนวณ

### 5.1 เอกสาร (doc) ที่เก็บ

```
{ v: 1, updatedAt: ISO, entries: [Entry], trades: [Trade] }

Entry = {
  id: "e_<random>", createdAt: ISO, updatedAt: ISO, deletedAt: ISO|null,
  date: "YYYY-MM-DD",                 // วันที่ตัดสินใจ (ค่าเริ่มต้น = วันนี้เวลากรุงเทพ แก้ย้อนหลังได้ตอนสร้าง)
  symbol: "NVDA" | "PTT.BK" | "BTCUSD", label: string,
  context: { event: string, feelings: ["fear"|"greed"|"fomo"|"confident"|"unsure"|"bored"|"regret"|"calm"], note: string },
  view:    { direction: "up"|"down"|"unsure", horizonDays: 7|30|90 },
  action:  { kind: "buy"|"sell"|"hold"|"none", plan: string, conviction: boolean, tradeIds: [string] },
  rules:   { ...§5.3 frozen },
  verdict: { compliance: "per-rule"|"against"|"n/a"|"unknown", supports: [...], opposes: [...], rulesSay, why: string },
  review:  { reviewedAt: ISO|null, selfVerdict: "right"|"wrong"|"mixed"|null, lesson: string }
}
Trade = { id: "t_<random>", createdAt, updatedAt, deletedAt|null, date, symbol, side: "buy"|"sell",
          qty: number, price: number, currency: "THB"|"USD", fee: number, note: string, entryId: string|null }
```

- **แช่แข็ง**: `context / view / action(kind, conviction) / rules / verdict / date / symbol` แก้ไม่ได้หลังบันทึก · แก้ได้เฉพาะ `review`, `action.plan`, `action.tradeIds` และ `Trade` ทุกช่อง (ไม้พิมพ์ผิดได้)
- **ลบ** = tombstone `deletedAt` (ซ่อนจากหน้า แต่คงไว้ใน doc เพื่อไม่ให้เครื่องอื่นชุบชีวิตกลับมาตอน merge) · tombstone เก็บแค่ `id/date/symbol/createdAt/updatedAt/deletedAt` (ตัดเนื้อหาทิ้งให้คืนพื้นที่ และซ่อมวันที่/สัญลักษณ์ที่เสียให้ผ่านตัวตรวจ — การลบรายการเสียจึงแก้ทางตันได้)
- **ผลจริง (+7/+30/+90) ไม่เก็บใน doc** — คำนวณตอนแสดงผลจากราคาจริง (§5.4) เพราะเป็นข้อเท็จจริงที่ตรวจซ้ำได้ ไม่ใช่ความเห็น

### 5.2 ราคา และแท่ง as-of

- แหล่งเดียว: `GET /api/ohlc?symbol=<providerSymbol>&start=<date − 730 วัน>` (ต้องได้ ≥ 200 แท่งก่อน as-of; 2 ปี ≈ 500 แท่ง) · ห้ามใช้ `/api/market-data` เพราะคืนเฉพาะ `closes` ไม่มี `low` (กฎแตะแล้วเด้งต้องใช้ low) และบนหน้าที่โหลด `data-snapshot.js` จะถูกดักคืนข้อมูลจาก snapshot แทนของสด
- `providerSymbol`: กติกาเดียวกับ `data-snapshot.js`: `BTCUSD → BTC-USD`, หุ้นไทยต้องมี `.BK`, อื่น ๆ ตามที่พิมพ์ (upper-case, ตัดอักขระนอก `A-Z0-9.^-`) · คีย์ที่เก็บคือ canonical (`BTCUSD`, `PTT.BK`)
- **แท่ง as-of** = แท่งสุดท้ายที่ `date ≤ entry.date` **และปิดตลาดแล้วจริง** วันที่ของแท่ง Yahoo เป็นวันท้องถิ่นของตลาด ส่วนเวลาปิดคิดเป็นเวลากรุงเทพจาก `marketOf(symbol)`:
  - `TH` (`.BK`): แท่งวันที่ D ปิดเมื่อ `now ≥ D 17:00`
  - `ASIA` (`.HK`, `.T`, `.SS`, `.SZ`, `.TW`, `.SI`): แท่ง D ปิดเมื่อ `now ≥ D 17:00`
  - `US` (ค่าเริ่มต้น): แท่ง D ปิดเมื่อ `now ≥ (D+1) 05:00` (ปิด 16:00 ET = 03:00/04:00 กรุงเทพ เผื่อไว้)
  - `CRYPTO` (`BTCUSD`, `*-USD`): แท่ง D ปิดเมื่อ `now ≥ (D+1) 07:00` (ปิด 00:00 UTC)
  - เอนจินรับ `nowBangkok` (ISO/`YYYY-MM-DDTHH:mm`) เป็นพารามิเตอร์ (pure, ทดสอบได้) · แท่งที่ยังไม่ปิดถูกทิ้ง บันทึก `partialBarDropped: true` และหน้าบอกว่า "ใช้ราคาปิด <asOfBar>"
  - ถ้าแท่ง as-of เก่ากว่า `entry.date` เกิน 7 วันปฏิทิน (เช่น Yahoo ล่ม ได้ cache เก่า `sourceType: SERVER_CACHED_DATA`) → **ห้ามบันทึก** บอกว่าราคายังไม่มาถึงวันนั้น · ภายใน 7 วัน → บันทึกได้พร้อม `staleSource: true` และคำเตือน
  - เวลา/วันที่ใช้ไม่ได้ (`nowBangkok` ผิดรูป หรือลงท้าย `Z`/offset อื่นที่ไม่ใช่ `+07:00`, หรือ `entry.date` ไม่ใช่ `YYYY-MM-DD`) → `blocked: "bad-input"` · วันที่บันทึกอยู่ในอนาคต (`entry.date > วันนี้กรุงเทพ`) → `blocked: "future"` · ทั้งสองกรณี **ห้ามบันทึก** (แยกจาก `"no-bars"` = สัญลักษณ์ไม่มีราคาย้อนหลัง ซึ่งบันทึกได้เป็น `unknown`)
  - หมายเหตุ: `/api/ohlc` ตั้งปลายช่วงข้อมูลที่เที่ยงคืน UTC แท่งไทยของวันนี้จึงอาจยังไม่มาจนถึง ~07:00 ของวันถัดไป ระบบใช้แท่งล่าสุดที่มีและแสดงวันที่ของแท่งเสมอ (ไม่เดา)
- ก่อนบันทึก ผู้ใช้ต้องกด **"ดูว่ากฎบอกอะไร"** ให้ระบบดึงราคาและแสดงผลกฎก่อน → ปุ่มบันทึกเปิดเมื่อการดึง **จบ** แล้ว (ได้แท่ง หรือได้ 0 แท่งอย่างชัดเจน) ไม่เปิดระหว่างดึงหรือเมื่อดึงล้มเหลว (กันพิมพ์สัญลักษณ์ผิดแล้วได้กฎของหุ้นอื่น) · แสดงชื่อ/ราคาปิดล่าสุดให้ยืนยันด้วยตา
- **สัญลักษณ์ที่ไม่มีราคาย้อนหลัง** (กองทุน RMF ใน holdings, หุ้นใหม่ < 26 แท่ง): บันทึกได้ กฎทุกข้อเป็น `na`, `compliance: 'unknown'`, หน้าแสดง "ไม่มีราคาย้อนหลังพอ ตัดสินกฎไม่ได้" ชัดเจน · ไม่กรอง datalist ทิ้ง แต่ติดป้ายประเภท
- รายการสัญลักษณ์ให้เลือก: `/api/portfolio-holdings` (เฉพาะ `isHolding`) + สัญลักษณ์ที่เคยบันทึก · พิมพ์เองได้ · ถ้า holdings ล้มเหลว ฟอร์มยังใช้ได้

### 5.4 ผลจริงภายหลัง (คำนวณตอนแสดง · pure)

- **ฐานราคา**: Yahoo ปรับราคาย้อนหลังเมื่อแตกพาร์ (split) ชุดราคาที่ดึงใหม่จึงอาจไม่ตรงกับ `rules.close` ที่แช่แข็งไว้ → `refClose = close ของชุดราคาปัจจุบันบนวัน rules.asOfBar` (ให้ ref และ actual มาจากชุดเดียวกัน) · ถ้า `|refClose / rules.close − 1| > 0.5%` ตั้ง `priceBasisChanged: true` และหน้าบอกว่า "ราคาย้อนหลังถูกปรับ (เช่น แตกพาร์) เทียบจากชุดราคาปัจจุบัน" · ถ้าชุดใหม่ไม่มีแท่งวันนั้น ใช้ `rules.close` พร้อมคำเตือน · ไม้จริงที่ผูกไว้ใช้ราคาไม้ (ไม่ปรับ split ใน V1 — ระบุในวิธีคิดว่าถ้าแตกพาร์ให้แก้จำนวน/ราคาไม้ตามโบรกเกอร์)
- ที่ `+7 / +30 / +90` วันปฏิทินจาก `entry.date`: `actualAt(bars, target, maxGapDays=7)` แบบ `btc-forecast-log.js` (ราคาปิดล่าสุดที่ไม่เกินวันเป้าหมาย ห่างได้ไม่เกิน 7 วัน ไม่งั้น `null`) → `pct = (actual/refClose − 1) × 100` · แท่งที่ยังไม่ปิด (กติกา §5.2) ไม่ใช้เป็น actual
- สถานะต่อช่วง: `pending` = **แท่งของวันเป้าหมายยังไม่ปิด** (`closedBarCutoff(marketOf(symbol), now) < target` หรือคิด cutoff ไม่ได้) — แก้ 2026-10-26: เดิมนับ "ถึงวันตามปฏิทิน" ทำให้คิดผลจากราคาวันก่อนแล้วตัวเลขเปลี่ยนหลังแท่งปิด · **หรือแท่งนั้นปิดแล้วแต่ยังไม่มาถึงในข้อมูลราคา** (`/api/ohlc` ส่งแท่งวัน D ประมาณ 07:00 กรุงเทพของ D+1 — ระหว่างนั้นยัง `pending` ไม่ใช้ราคาวันก่อนแทน) · `scored` · `no-data` (ช่วงที่เป็น `no-data` ให้ `date`/`close`/`pct` เป็น `null` ทั้งหมด)
- **คาดถูก/ผิด** ที่ช่วง `view.horizonDays`: `up` ถูกเมื่อ `pct > +2` · `down` ถูกเมื่อ `pct < −2` · `|pct| ≤ 2` = `flat` (ไม่นับถูกหรือผิด — ผู้ใช้ยืนยัน 2026-10-26: "ขยับ ±2% ถือว่าทรงตัว") · `unsure` = ไม่ตัดสิน
- **ผลของ action** ที่ช่วงเดียวกัน: เช็คแถบทรงตัวก่อน `|pct| ≤ 2` = `flat` (แถบเดียวกับ "คาดถูก/ผิด": ขยับไม่เกิน 2% ไม่นับว่าดีหรือไม่ดี) · ไม่งั้น `buy` ดีเมื่อ `pct > 0` · `sell` ดีเมื่อ `pct < 0` ("ขายแล้วลง") · ไม่ดีกลับกัน · `hold/none` ไม่ตัดสิน
- เคสขายแล้วซื้อกลับ: ถ้า entry (action sell) มี `tradeIds` ที่มีไม้ sell และไม้ buy ตัวเดียวกันที่วันหลังกว่า → แสดง "ซื้อกลับแพงกว่าที่ขาย +x% (+y ต่อหน่วย)" จากราคาไม้จริง

### 5.5 ไม้จริง (FIFO)

- เรียงต่อสัญลักษณ์ตาม `(date, ซื้อก่อนขายในวันเดียวกัน, createdAt)` (แก้ 2026-10-26: ไม้ขายที่กรอกก่อนไม้ซื้อวันเดียวกันเคยกลายเป็นขายเกิน) · ไม้ขายดึงล็อตซื้อที่เก่าสุดก่อน · กำไรที่รับรู้ต่อไม้ขาย = Σ(`(sellPrice − lotPrice) × qtyMatched`) − `fee` ของไม้ขาย × (`matchedQty / qty`) − ค่าธรรมเนียมซื้อตามสัดส่วน
- ขายเกินที่ถือ → คำนวณเฉพาะส่วนที่จับคู่ได้ (ค่าธรรมเนียมขายคิดตามสัดส่วนที่จับคู่) และติดป้ายเตือน "ขายมากกว่าที่บันทึกซื้อไว้" (ห้ามเงียบ)
- **สกุลเงินต่อสัญลักษณ์มีสกุลเดียว** = สกุลของไม้แรกที่ใช้ได้ของสัญลักษณ์นั้น · ไม้ (ซื้อหรือขาย) ที่สกุลไม่ตรง → ไม่นำมาคิด + เตือน "สกุลเงินไม่ตรงกับไม้ก่อนหน้า" (ห้ามบวกลบข้ามสกุล) · ค่าธรรมเนียมติดลบ = ไม้ไม่ถูกต้อง ไม่นำมาคิด + เตือน
- ล็อตที่เหลือ = ไม้เปิดอยู่: กำไรลอยตัวจากราคาปิดล่าสุด (`/api/ohlc`) พร้อมวันที่ราคา · ถ้าแท่งล่าสุดยังไม่ปิด (กติกา §5.2) ใช้ได้แต่ติดป้าย "แท่งยังไม่ปิด"
- ถ้าสกุลของไม้ต่างจากสกุลของราคาตลาด (`open[].priceCurrency` — BTC และหุ้นสหรัฐ = USD · `.BK` = THB) เช่นซื้อ BTC เป็นบาทจาก exchange ไทย → กำไรลอยตัวเป็น `null` (แสดง "—" พร้อมเหตุผล) ไม่ลบข้ามสกุล · ไม่แปลงสกุลใน V1
- สกุล: `.BK → THB` · อื่น ๆ `USD` (รวม BTCUSD) · แก้ได้ในฟอร์ม · รวมยอดแยกสกุล ไม่แปลง
- ฟอร์มบันทึกความคิดเลือก "บันทึกไม้จริงพร้อมกัน" ได้ → สร้าง Trade และผูก `entryId/tradeIds` ให้ · เพิ่มไม้เดี่ยวจากส่วนไม้จริงก็ได้ (ผูก entry ทีหลังได้)

### 5.6 สถิติ (pure · เฉพาะรายการที่ `scored` ที่ช่วงของตัวเอง)

- ตาม `verdict.compliance` (`per-rule` vs `against`): จำนวน · สัดส่วนที่ action ให้ผลดี · เฉลี่ย `pct` ในทิศของ action (ขาย = −pct)
- ตามอารมณ์ (`feelings` ติ๊กได้หลายอัน นับทุกอันที่ติ๊ก): จำนวน · สัดส่วนคาดถูก · เฉลี่ย pct ในทิศ action
- ตามคาดการณ์: คาดถูก / ผิด / flat / ไม่ตัดสิน
- `n < 3` → แสดงจำนวนอย่างเดียว ไม่แสดงเฉลี่ย/สัดส่วน พร้อมคำว่า "ยังน้อยเกินสรุป"
- ทุกกลุ่ม (ตามกฎ/แหกกฎ และตามอารมณ์) นับทั้ง **ผลของ action** (`goodN` จาก `actionResult`) และ **คาดถูก** (`rightN`, `wrongN`, `judgedN` จาก `predicted` ที่ช่วงของตัวเอง scored แล้ว) — "สัดส่วนคาดถูก" = `rightN / judgedN` · รายการที่ลบแล้ว (`deletedAt`) ไม่นับเสมอ · `predEnough` (`judgedN ≥ 3`) คุมการแสดงสัดส่วนคาดถูก แยกจาก `enough` (`scoredN ≥ 3`) ที่คุมผลของ action · `byPrediction.unjudged` = จำนวนที่คาดว่า "ไม่แน่ใจ"

## 6. ที่เก็บข้อมูล และการซิงก์

- **ตัดสินใจแล้ว**: เก็บบนเซิร์ฟเวอร์เดิม (Supabase `app_state`) แต่**แยกแถว** `id = "decision_journal_main"` ผ่าน endpoint เดิม `GET/PUT /api/portfolio?doc=journal` (ไม่เพิ่มฟังก์ชัน — โควตา Vercel 12/12 เต็ม) · ไม่ใส่ `doc` = พฤติกรรมเดิมทุกอย่าง
- เหตุผลที่ไม่ใส่ใน blob พอร์ต: `app.js adoptServerAllocation` (`app.js:159-166`) รีเฟรชเฉพาะ `allocation` ก่อน PUT → แท็บ Quarterly Editor ที่เปิดค้างจะเขียนทับคีย์อื่นที่เพิ่งบันทึกจากเครื่องอื่น; และ "Load Latest Data" ก๊อป blob ทั้งก้อนลง localStorage snapshot (`data-snapshot.js:387`) ซึ่งไม่ควรมีข้อความบันทึกส่วนตัวปนอยู่
- รหัสผ่าน: header เดิมผ่าน `api-auth.js` (หน้าไม่ต้องใส่เอง) · 401 เปิดหน้าล็อกอินเอง
- **ตรวจสอบฝั่งเซิร์ฟเวอร์** (`lib/journal-validation.js` ใช้ทั้ง `api/portfolio.js` และ `server.js`): `data` เป็น object · `v === 1` · `entries`/`trades` เป็น array · ทุก entry/trade มี `id` string, `date` รูปแบบ `YYYY-MM-DD`, `symbol` string · **ขนาด JSON ไม่เกิน 900,000 ไบต์ UTF-8** (`JOURNAL_MAX_BYTES`, แก้ 2026-10-26: เดิมนับตัวอักษร 1.5 ล้าน ซึ่งข้อความไทยเกิน 4.5 MB ชนลิมิต body ของ Vercel ก่อนตัวตรวจจะได้ตอบ) · ไม่ผ่าน → 400 ไม่เขียน
- **ฝั่งหน้าเว็บมีกติกาชุดเดียวกัน** (`DecisionJournal.itemProblems(item)` และ `MAX_DOC_BYTES`) เพื่อไม่ให้สร้างรายการที่เซิร์ฟเวอร์จะปฏิเสธ (เช่นพิมพ์สัญลักษณ์ภาษาไทย "ปตท" ซึ่ง canonical ได้ค่าว่าง) — ไม่งั้นรายการเสียตัวเดียวในร่างจะทำให้บันทึกไม่ได้ตลอดไป · เทสต์เทียบสองชุดกติกาบนเคสเดียวกันกันแยกทาง · หน้าเตือนเมื่อขนาดเกิน 80%
- **`server.js` ต้อง mirror** branch เดียวกัน (local dev ไม่รัน `api/portfolio.js`) รวม local-fallback → `.local-data/decision-journal.json` (โฟลเดอร์ปรับได้ด้วย env `LOCAL_DATA_DIR` สำหรับเทสต์) · ตัวอ่าน body ของ `server.js` ต้องรวม Buffer แล้วถอดรหัส UTF-8 ครั้งเดียว (แก้ 2026-10-26: เดิมต่อ string ทีละ chunk ทำให้ตัวอักษรไทยที่ถูกตัดกลาง chunk กลายเป็น U+FFFD — กระทบข้อมูลพอร์ตใน local dev ด้วย) และเกิน 1,000,000 ไบต์ตอบ 413 JSON แทนการตัดการเชื่อมต่อ · `server.js` ไม่เปิด port เมื่อถูก `require` (เปิดเฉพาะ `node server.js`) เพื่อให้เทสต์เรียก `handlePortfolio` ตรง ๆ ได้
- **ฝั่งหน้าเว็บ**: โหลด doc ตอนเปิดหน้า · ทุกครั้งที่บันทึก: GET สด → `merge(server, local)` ตาม `id` (เลือกรายการที่ `updatedAt` ใหม่กว่า, tombstone ชนะถ้าใหม่กว่า) → PUT ทั้ง doc · ไม่มีกล่องขัดแย้งเพราะ merge รายรายการ
- PUT ล้มเหลว → เก็บร่างใน `localStorage decision_journal_draft_v1` + บอกตรง ๆ ว่ายังไม่ถึงเซิร์ฟเวอร์ (ห้ามขึ้น "บันทึกแล้ว") · เปิดหน้าใหม่แล้ว merge ร่างกลับและลองส่งอีก
- Export/Import JSON (merge ตาม id) แบบ `thai-dr-page.js` สำหรับสำรอง
- cache ราคาใน `localStorage decision_journal_ohlc_v1` ต่อสัญลักษณ์ ประทับวัน (กรุงเทพ) · ดึงพร้อมกันไม่เกิน 4
