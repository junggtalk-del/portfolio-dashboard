# Bitcoin ใน Quarterly Editor กรอกเป็นจำนวน BTC — design (ฉบับสั้น)

2026-11-25 · ผู้ใช้อนุมัติในแชต ("ตรง จัดไปเลย")

## ทำไม

ผู้ใช้ไม่อยากคิดมูลค่าบาทของ Bitcoin ใหม่ทุกครั้งที่ราคาเปลี่ยน อยากกรอก "จำนวน BTC" แล้วให้ระบบแปลงเป็นบาทตามราคา
และให้มูลค่าบาทนั้นเป็นมูลค่า Bitcoin ของพอร์ตในทุกหน้า (แนวเดียวกับมูลค่าหุ้นนอกที่ตามราคาปิด — d248d8a)

## สิ่งที่ผู้ใช้กำหนด (ของผู้ใช้)

- แถว Bitcoin: ช่อง "มูลค่าปัจจุบัน" เปลี่ยนเป็น **จำนวน BTC**
- จำนวนที่กรอก = **ยอดรวม BTC ที่คาดว่าจะมี** = BTC ที่ซื้อแล้ว + เงินสดรอซื้อที่ผู้ใช้แปลงเป็น BTC เอง
- **% ลงทุนจริง** กรอกเองเหมือนเดิม (ส่วนที่เหลือ = รอซื้อ)
- มูลค่าบาท = จำนวน BTC × ราคา BTC × USD/THB → ใช้ทุกหน้า
- ผลที่ผู้ใช้รับทราบ: ส่วนรอซื้อนับเป็น BTC จึงขยับตามราคา BTC ด้วย (เงินสดจริงไม่ขยับ) จนกว่าผู้ใช้ปรับจำนวน/% เอง

## Approaches

| | วิธี | ได้ | เสีย |
|---|---|---|---|
| **A (เลือก)** | เขียนมูลค่าบาทกลับลงเอกสารไตรมาส (แถว bitcoin ของไตรมาสล่าสุด) ทุกครั้งที่มีราคาใหม่ | ผู้อ่าน ~8 หน้าใช้ `manualValue` เดิม ไม่ต้องแก้ · ทุกหน้า/ทุกเครื่องเลขเดียวกัน · ตรงกับแนวที่ผู้ใช้อนุมัติเมื่อวาน | ต้องกันการเขียนเอกสารชนกันในหน้าเดียว (ล็อกร่วม) |
| B | เก็บจำนวน แล้วให้ทุกหน้าคำนวณตอนอ่าน (แบบ `ForeignSleeve.applyToDoc`) | สดทุกหน้าเสมอ | แก้ ~8 หน้า + เอนจิน · ค่าในเอกสารค้าง · ประวัติไตรมาสยังต้องเขียนกลับอยู่ดี |
| C | คำนวณเฉพาะใน Editor ตอนบันทึก | ง่ายสุด | หน้าอื่นค้างเลขเก่าจนกว่าจะเปิด Editor — ขัดกับ "ใช้ทุกหน้า" |

## การตัดสินใจ (ของผม — ผู้ใช้ได้เห็นและอนุมัติแล้ว)

1. **เก็บในแถว bitcoin**: `btcQty` (number ≥ 0) · `btcPriceUsd` · `usdThb` · `btcValuedAt` (ISO เวลาของราคา) · `manualValue = snapshotValue = round2(btcQty × btcPriceUsd × usdThb)`
2. **ราคา**: BTC-USD ล่าสุดจาก Load Latest Data (`snapshot.historicalData.BTCUSD` → `technicalSignals.BTCUSD`) · เวลา = `lastUpdated` ของซีรีส์ (ไม่มี → `loadedAt`) · USD/THB = ECB `frankfurter.dev/v1/latest` แคชรายวัน (ดึงไม่ได้ = ค่าที่แคชล่าสุด · ไม่มีเลย = ไม่ปรับ)
3. **ไม่ใช้ราคาที่เก่ากว่าที่เก็บไว้**: แถวที่ประเมินด้วยราคาใหม่กว่าแล้ว (เครื่องอื่น) ห้ามถูกทับด้วยราคาเก่า — ราคาที่ใช้ = ตัวใหม่กว่าระหว่างราคาที่เก็บในแถวกับราคาใน snapshot
4. **ไตรมาสที่ตามราคา** = ไตรมาสล่าสุดของเอกสารที่ยังไม่จบตามปฏิทิน · ไตรมาสอื่นไม่แตะ (ประวัติ/QoQ ค้าง) · ในไตรมาสอื่น ฟอร์มแถว bitcoin กรอกบาทเหมือนเดิม
5. **อัปเดตเมื่อ**: หลัง Load Latest Data (หน้าไหนก็ได้) + ตอนเปิดหน้า (เช็คในเครื่องก่อน ไม่มีอะไรเปลี่ยน = ไม่ยิง network) · GET เอกสารสด → แก้เฉพาะแถว bitcoin ของไตรมาสนั้น → PUT → อัปเดตสำเนาใน snapshot (หน้าอื่นวาดใหม่ตาม event เดิม)
6. **ล็อกร่วม**: ทุกการ GET→PUT ของ `/api/portfolio` ในหน้าเดียวกันผ่าน `PortfolioCore.withDocLock` — โมดูลใหม่, Editor (`persistRemoteData`), หน้า PM (บันทึกเงินสด + ซิงก์แถวหุ้นนอก), การ์ด allocation, หน้า Asset Allocation
7. **Editor**: บันทึก/คัดลอกไตรมาส/แช่ไตรมาส คำนวณบาทจากจำนวนก่อนส่งเสมอ · คัดลอกจากไตรมาสก่อนคัดลอกจำนวน BTC ด้วย · แถวเดิมที่ยังไม่มีจำนวน = ใช้บาทเดิมจนกว่าผู้ใช้กรอก · ไม่มีราคา = ไม่ให้บันทึกแถว bitcoin ใหม่ พร้อมบอกให้กด Load Latest Data
8. **Privacy Lock**: จำนวน BTC = ข้อมูลเงิน → ตอนล็อกแสดง "XXX BTC" · ช่องกรอกตอนแก้ไขวาดว่าง + placeholder (กติกาเดียวกับช่องเงิน) · ไม่มี ฿ ใน title/aria
9. **แถว BTC ในรายการหุ้น** (`/api/portfolio-holdings`): ถ้ามีแถว BTC ที่ถือ **แถวเดียว** → `marketValue` = Σ (มูลค่าแถว bitcoin ของไตรมาสที่ตามราคา × % ลงทุนจริง) · ไม่มี = ไม่ทำ · มีหลายแถว = ไม่ทำ (กำกวม)
10. **ไม่เปลี่ยน**: หน้าที่แสดงราคา BTC เป็นดอลลาร์ (Bitcoin Monitor, Smart DCA ฯลฯ)

## ข้อจำกัด

- โค้ดใหม่ใน `public/` เป็น ES5 · ข้อความไทย · ไม่มีคำแนะนำซื้อ/ขาย · ไม่แตะเอกสารพอร์ตจริงตอนทดสอบ
- server รับ PUT ทั้งเอกสารเท่านั้น (ไม่มี op) → ต้อง GET สดก่อน PUT ทุกครั้ง และเอกสารว่าง/ไม่มีไตรมาส = ไม่ PUT
- เขียนเอกสารเฉพาะเมื่อค่าจริงเปลี่ยน (คำนวณซ้ำด้วยราคาเดิม = ไม่มีอะไรเปลี่ยน · ไม่วน event)
