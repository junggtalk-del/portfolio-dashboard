# การ์ด "Asset allocation" บนหน้า /portfolio — design (2026-11-07)

## เจตนา

ผู้ใช้อยากเห็นในจอเดียวว่าเงินอยู่ที่ไหน: ลงทุนในแต่ละก้อนไปเท่าไร กันเงินสดไว้ "รอซื้อ" ให้ก้อนไหนเท่าไร เงินสดที่ยังไม่จัดสรรมีเท่าไร และเงินสดนั้นอยู่ตรงไหนของกรอบ 1–3 ล้านบาทที่ตัวเองตั้งไว้สำหรับช่วง bear/bull — แล้วตัดสินใจโยกเงินเอง **ระบบไม่แนะนำอะไร** (คำพูดผู้ใช้: "การตัดสินใจว่าจะโยกเงินช่วง bull bear ระบบไม่ต้องแนะนำอะไร ฉันจะโยกเอง")

ภาพสเก็ตช์ของผู้ใช้: กราฟแท่งต่อก้อน (ส่วนทึบ "ถืออยู่" + ส่วนบน "รอซื้อ") · แกนตั้งเป็นเงิน · แถบ Cash 1–3 ล้านด้านล่าง · ลูกศร bear ↑ (เงินสดเข้าสินทรัพย์) / bull ↓ (สินทรัพย์ออกเป็นเงินสด) · ผู้ใช้ตัดทองคำออก

mockup ที่เลือก: แบบ A รุ่น 5 ใน `.superpowers/brainstorm/1830-1794001233/content/allocation-card-v5.html` (ต่างจากรุ่น 5 สองข้อ: ช่อง "เงินสดทั้งหมด" ไม่มีแถบสี แสดงแค่ยอดเงิน · ปุ่ม "ตั้งยอดรอซื้อ" เปลี่ยนเป็น "ตั้งกรอบเงินสด" เพราะยอดรอซื้ออ่านจาก Editor — ผู้ใช้สั่งหลังรุ่น 5)

## เป้าหมาย

1. การ์ดใหม่บนหน้า /portfolio (หน้า Portfolio Position) ชื่อ "Asset allocation" แสดง 5 ก้อน: Bitcoin · หุ้นต่างประเทศ · กองทุนหุ้น (เงินสำรองเลี้ยงชีพ) · กองทุน RMF · หุ้นไทย
2. แท่งต่อก้อน แกนตั้ง = ล้านบาท · ส่วนทึบ = เงินที่ลงทุนจริง พร้อม % ของก้อนตัวเอง · ส่วนลาย = ยอดรอซื้อที่ผู้ใช้ตั้ง พร้อม % ของก้อนตัวเอง · ใต้แท่ง = ชื่อก้อน + % ของความมั่งคั่งรวม (ของทั้งแท่ง = ลงทุนแล้ว + รอซื้อ — ผู้ใช้สั่ง 2026-11-07 หลัง implement) · ตัวเลขของแต่ละส่วนอยู่ในส่วนนั้น (ตัวเลขรอซื้ออยู่ในกรอบประ ตัวใหญ่อ่านชัด) — ส่วนที่เตี้ยเกินใส่ไม่พอดีให้ขึ้นเป็นป้ายลอยเหนือยอดแท่ง หน้าตาเหมือนส่วนของตัวเอง (ผู้ใช้สั่ง 2026-11-07 หลัง implement) · **ไม่มีคำว่า "เป้า" บนแท่ง**
3. แถบภาพรวม 2 ช่อง: "ลงทุนในสินทรัพย์จริง" (บาท · % ของความมั่งคั่ง) และ "เงินสดทั้งหมด = เงินสดใน Editor + รอซื้อทุกก้อน" (บาท · % · บรรทัดแจกแจง: ยังไม่จัดสรร X · รอซื้อ Bitcoin a · หุ้นนอก b · หุ้นไทย c = รวม Y) — **แสดงแค่ยอดเงิน ไม่มี bar chart ในช่องนี้**
4. แถบเงินสดด้านล่าง: เงินสดจาก Quarterly Editor เทียบกรอบ ต่ำ–สูง (ค่าเริ่มต้น 1–3 ล้าน แก้ได้) จุดบอก "ตอนนี้ X" + ข้อความสองฝั่ง "bear ↑ กติกาของคุณ: ลดเงินสดลงไปทาง <ต่ำ> ล้าน เอาไปซื้อก้อนที่ยังรอซื้อ" / "bull ↓ กติกาของคุณ: พักกำไรเป็นเงินสดขึ้นไปทาง <สูง> ล้าน" — เป็นการทวนกติกาของผู้ใช้ ไม่ใช่คำแนะนำ
5. ปุ่ม "ตั้งกรอบเงินสด" กางช่องกรอกกรอบเงินสด ต่ำ/สูง (ล้านบาท) · บันทึกไว้กับข้อมูลพอร์ตบนเซิร์ฟเวอร์ · **ไม่มีช่องกรอกยอดรอซื้อ** — ยอดรอซื้อมาจาก Quarterly Editor (ผู้ใช้ยืนยัน 2026-11-07: ยอดรอซื้อ = ส่วน "ยังไม่ลงทุน" ของรายการใน Editor)
6. เงินทุกตัวซ่อนเป็น XXX ตอน Privacy Lock · ใช้ได้บนมือถือ

## ไม่ทำ

- ไม่แนะนำให้ซื้อ/ขาย/โยก ไม่มีสถานะ "ควร…" ไม่มีสัญญาณ — แถบเงินสดบอกแค่ว่าอยู่ต่ำกว่า/ในกรอบ/สูงกว่ากรอบ เป็นข้อเท็จจริง
- ไม่มีตารางต่อก้อน (ผู้ใช้ตัดออก "ดูแล้วเกะกะ") · ไม่มีทองคำ · ไม่มีแถบสีในช่องเงินสดทั้งหมด
- ไม่แตะเอนจิน Asset Allocation เดิม (`asset-allocation-engine.js` = ผลตอบแทน 3 ระยะ คนละเรื่อง) และไม่เปลี่ยนบล็อก "สัดส่วนพอร์ตตอนนี้" ที่มีอยู่
- ไม่คิดจำนวนหุ้น/ราคา — ทุกตัวเลขเป็นมูลค่าบาทจาก Quarterly Editor + ตัวเลขที่ผู้ใช้กรอก

## สิ่งที่ถือว่าล้มเหลวแม้ใช้งานได้

- ตัวเลข % ใช้ฐานคนละตัวโดยไม่บอก (บทเรียน 9arm "ฐาน % คนละตัว") — ทุก % ต้องมีคำกำกับว่า "ของก้อนนี้" หรือ "ของความมั่งคั่ง"
- ยอดรอซื้อ/กรอบเงินสดที่กรอกแล้วหายเมื่อโหลดใหม่ หรือการบันทึกไปทับ quarters/allocation ที่อีกแท็บเพิ่งแก้
- เงินบาทโผล่ตอนล็อก (รวมใน title/aria-label)
- การ์ดหายเมื่อหน้า position วาด `#ppRoot` ใหม่

## นิยามตัวเลข (ผู้ใช้ตัดสินแล้ว เว้นที่ระบุว่าเดา)

แหล่ง: ไตรมาสล่าสุดใน Quarterly Editor (`GET /api/portfolio` สด เหมือน asset-allocation-page · ไม่ใช่ snapshot) — รายการ `assets[]` แต่ละตัวมี `type` และมูลค่า (ดูวิธีรวมใน `PortfolioPosition.compute` / บล็อก "สัดส่วนพอร์ตตอนนี้" ของ portfolio-position-page.js ซึ่งรวมตาม `type`)

| ก้อน | type ใน Editor |
|---|---|
| Bitcoin | `bitcoin` |
| หุ้นต่างประเทศ | `foreign-stock` |
| กองทุนหุ้น | `provident-fund` (ผู้ใช้สั่ง 2026-11-07 หลัง implement: แยกเงินสำรองเลี้ยงชีพเป็นแท่งของตัวเอง ใช้ชื่อ "กองทุนหุ้น" บนกราฟ — เดิมรวมในแท่งหุ้นนอก) |
| กองทุน RMF | `rmf-jang` + `rmf-tum` |
| หุ้นไทย | `thai-stock` |
| เงินสด (Editor) | `cash` |
| ไม่มีแท่ง แต่รวมในความมั่งคั่ง (เดา) | `custom` |

- ทุกรายการใน Editor มี `investedPercent` (0–100) · ส่วนที่ลงทุนแล้วของรายการ = `value × investedPercent/100` · ส่วนที่ยังไม่ลงทุน = ที่เหลือ — **ยอดรอซื้อของก้อน = ผลรวมส่วนที่ยังไม่ลงทุนของรายการ type นั้น** (ผู้ใช้ยืนยัน) → ไม่มีการกรอกเอง ไม่มีคีย์ waitByClass
- `held[c]` = Σ ส่วนที่ลงทุนแล้ว ของรายการ type c · `wait[c]` = Σ ส่วนที่ยังไม่ลงทุน ของรายการ type c · `classTotal[c] = held + wait` = มูลค่ารวมของก้อนใน Editor · % ในแท่ง: `held/classTotal` และ `wait/classTotal` (wait = 0 → ทึบ 100% ไม่มีส่วนลาย)
- `invested` = Σ ส่วนที่ลงทุนแล้วของทุกรายการที่ไม่ใช่ type cash (provident-fund มีแท่ง "กองทุนหุ้น" ของตัวเอง · custom ไม่มีแท่ง — บอกในบรรทัดย่อยว่า "รวมอื่น ๆ ที่ไม่มีแท่ง ฿X" เมื่อมี) — **ต้องเท่ากับ "ลงทุนจริง" ในส่วนหัวของหน้า** (`summaryStrip` / `getTotals` ของ app.js) ตัวเลขเดียวกัน สูตรเดียวกัน
- `cashEditor` = Σ มูลค่ารายการ type cash · `waitSum` = Σ wait ของทุกรายการที่ไม่ใช่ cash · `cashTotal = cashEditor + waitSum` — **ต้องเท่ากับ "เงินสด/ยังไม่ลงทุน" ในส่วนหัวของหน้า**
- `wealth = invested + cashTotal` = ความมั่งคั่งรวมของ Editor (ตัวเดียวกับส่วนหัว) · % ของความมั่งคั่งใต้แท่ง = `classTotal[c]/wealth` = (ลงทุนแล้ว + รอซื้อ) ÷ ความมั่งคั่ง (ผู้ใช้สั่ง 2026-11-07 หลัง implement — เดิม `held[c]/wealth` · ตรงกับบล็อก "สัดส่วนพอร์ตตอนนี้") · % ของช่องภาพรวม = `invested/wealth`, `cashTotal/wealth` · การ์ดต้องไม่มีฐาน % ใดที่ต่างจากส่วนหัวของหน้า
- ถ้า `PortfolioPosition.compute` / app.js มีฟังก์ชันรวมยอดเหล่านี้อยู่แล้ว ให้เรียกใช้ตัวเดียวกัน (ห้ามเขียนสูตรใหม่คนละที่) และมีเทสต์ยืนยันว่าตัวเลขการ์ดเท่ากับส่วนหัวบน fixture เดียวกัน
- แถบเงินสด: เปรียบเทียบ `cashEditor` (ไม่ใช่ cashTotal — ผู้ใช้ยืนยัน) กับ `cashBand = { min, max }` ค่าเริ่มต้น 1,000,000 / 3,000,000 · สเกลแถบ 0 … max(max × 1.33, cashEditor × 1.1) · ป้ายใต้แถบ "0 · <min> ล้าน · <max> ล้าน" · สถานะข้อความ (ข้อเท็จจริง): ต่ำกว่ากรอบ / ในกรอบ / สูงกว่ากรอบ
- ไม่มีไตรมาสใน Editor → การ์ดบอก "ยังไม่มีข้อมูลใน Quarterly Editor" ไม่วาดแท่ง · ก้อนที่มูลค่า 0 และไม่มี wait → แท่งว่างพร้อมป้าย "—"
- ปัดเศษเฉพาะตอนแสดง: ล้านบาท 1 ตำแหน่ง (≥ 10 ล้าน → 0 ตำแหน่ง? ไม่ — คง 1 ตำแหน่งเสมอ) · % จำนวนเต็ม

## ที่เก็บค่าที่ผู้ใช้กรอก

- คีย์ระดับบนใหม่ในเอกสาร `/api/portfolio`: `allocationPlan = { cashBand: { min, max } (บาท · ค่าเริ่มต้น 1,000,000 / 3,000,000 · min ≤ max · ≥ 0), updatedAt: iso }` — ค่าที่ผู้ใช้กรอกมีแค่กรอบเงินสด
- บันทึกแบบเดียวกับ `asset-allocation-page.js`: GET สด → ใส่ `allocationPlan` ของเรา → PUT ทั้งเอกสาร (ห้ามทับ `quarters`/`allocation` ที่สดกว่า — ใช้แนวทาง/โค้ดร่วมกับหน้านั้นถ้าทำได้) · ล้มเหลว → ร่าง localStorage `allocation_plan_draft_v1` + ข้อความไทย แล้วลองใหม่เมื่อเปิดหน้า
- **ผู้สร้างต้องตรวจว่า `public/app.js` (Quarterly Editor) และ `asset-allocation-page.js` เวลา PUT ยังคงคีย์ `allocationPlan` ไว้** (ถ้า PUT จาก object ที่สร้างใหม่ คีย์จะหาย) — ถ้าไม่คง ต้องแก้ให้คง และมีเทสต์
- เซิร์ฟเวอร์ (`server.js` local + `api/portfolio.js`) ต้องรับคีย์ใหม่ผ่าน validation ที่มีอยู่ (ตรวจก่อน)
