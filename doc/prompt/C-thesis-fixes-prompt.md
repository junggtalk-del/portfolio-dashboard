## Fix 1A — เปลี่ยน P/E percentile ไปใช้ข้อมูลรายวัน (แก้ 3 บั๊กพร้อมกัน)

**อาการปัจจุบัน:** P/E ปัจจุบัน ~34.5 แต่ป้ายซ้ายของแถบบอก "ต่ำสุด ~38.3" — ค่าปัจจุบันหลุดออกนอกช่วงอ้างอิง ตัวชี้เลยติดขอบและแสดงเป็น `percentile 0` ซึ่งผิดความหมาย

**สาเหตุ:** ชุดอ้างอิงใช้ P/E ณ สิ้นปีบัญชีแค่ 5 จุด และคำนวณคนละฐานกับตัวปัจจุบัน (สิ้นปี × EPS ทั้งปี vs live × TTM)

**วิธีแก้ — สร้าง P/E รายวัน:**

สำหรับทุกวันทำการ `d` ในช่วงที่มีข้อมูล:

```
TTM_EPS(d) = ผลรวม EPS 4 ไตรมาสล่าสุดที่ "ประกาศแล้ว" ณ วันที่ d
PE(d)      = price(d) / TTM_EPS(d)
```

ข้อบังคับ:

- **ต้องใช้วันประกาศงบ ไม่ใช่วันสิ้นงวด** — ณ วันที่ 1 ส.ค. ตลาดยังไม่รู้ผลไตรมาสที่จบ 30 มิ.ย. ถ้าใช้วันสิ้นงวดจะเกิด look-ahead bias และ P/E ในอดีตจะดูถูกกว่าความจริง
- **ต้องปรับ split ให้สอดคล้องกันทั้งราคาและ EPS** ตรวจว่าทั้งสอง series ปรับ split แล้วหรือยัง ถ้าปรับคนละแบบ P/E ในอดีตจะผิดเป็นเท่าตัว รายงานผลการตรวจนี้ด้วย
- **ตัดวันที่ `TTM_EPS(d) <= 0` ออก** และรายงานจำนวนวันที่ถูกตัด (P/E จากกำไรติดลบไม่มีความหมาย)
- ตัวเลข P/E ปัจจุบันต้องคำนวณด้วยสูตรเดียวกันเป๊ะ ต่างแค่ใช้ราคา live

**การแสดงผล:**

- แถบใช้ min / median / max ของชุดรายวัน
- percentile เป็นจำนวนเต็ม
- ใต้แถบระบุของจริง: `อิงข้อมูลรายวัน N วัน · YYYY-MM ถึง YYYY-MM`
- ถ้ามีวันที่ใช้ได้ **น้อยกว่า 250 วัน** ให้ปิดแถบ แสดงข้อความ `ช่วงข้อมูลสั้นเกินไป` แล้วไป Fix 1B

**กรณีค่าปัจจุบันหลุดนอกช่วง** (ยังเกิดได้แม้ใช้รายวัน):

- ห้ามแสดง `percentile 0` หรือ `percentile 100`
- ให้แสดง `ต่ำกว่าช่วงอ้างอิงทั้งหมด` หรือ `สูงกว่าช่วงอ้างอิงทั้งหมด`
- ตัวชี้วาดที่ขอบแถบพร้อมสัญลักษณ์ลูกศรชี้ออกนอกกรอบ ให้เห็นชัดว่าอยู่นอกช่วง

## Fix 1B — บรรทัดสรุปภาษาคน (ทำเสมอ ไม่ว่า 1A จะสำเร็จหรือไม่)

เพิ่มบรรทัดเดียวไว้ **บนสุดของ §14** เหนือการ์ดทั้งหมด:

```
P/E ~34.5 · ต่ำกว่ามัธยฐาน 5 ปี ~33%
```

- คำนวณจาก `(PE_ปัจจุบัน − PE_มัธยฐาน) / PE_มัธยฐาน`
- ใช้คำ `ต่ำกว่า` / `สูงกว่า` ตามทิศทาง
- ระบุจำนวนปีอ้างอิงจริง
- บรรทัดนี้ต้องแสดงได้แม้แถบ percentile ถูกปิด เพราะมันเป็นข้อความที่ตรงและปลอดภัยกว่า percentile

**เพิ่มคำเตือนช่วงอ้างอิงใต้แถบ** — ข้อความคงที่:

```
ช่วงอ้างอิงคือ 5 ปีที่ผ่านมาเท่านั้น ไม่ใช่การเทียบกับตลาดหรือกลุ่มอุตสาหกรรม
```

## Fix 2 — แก้ label การ์ดที่สามใน §15

**อาการ:** การ์ดชื่อ `ความสม่ำเสมอ 5.3pp` อ่านกลับด้าน — ค่ายิ่งสูงยิ่ง**ไม่**สม่ำเสมอ แต่ชื่อทำให้ดูเหมือนยิ่งสูงยิ่งดี

**แก้เป็น:**

- ชื่อการ์ด → `ช่วงของ magnitude`
- ค่าหลัก → แสดงเป็นช่วง min–max เช่น `+2.1% ถึง +15.4%`
- ข้อความเล็กใต้ค่า → `ส่วนเบี่ยงเบนมาตรฐาน ~5.3pp — ยิ่งสูง ขนาด beat ยิ่งคาดเดายาก`

ช่วง min–max อ่านเข้าใจทันทีโดยไม่ต้องรู้ว่า standard deviation คืออะไร

## Fix 3 — เพิ่มบริบทความผันผวนในบรรทัดตีความ

บรรทัดตีความปัจจุบันมี 4 แบบตายตัว **คงไว้ทั้ง 4 แบบ** แต่เพิ่มเงื่อนไขต่อท้าย:

- ถ้าส่วนเบี่ยงเบนมาตรฐานของ `magnitudePct` **> 4pp** ให้ต่อท้ายด้วย ` · ขนาด beat คาดเดายาก`

ห้ามเพิ่มข้อความตีความแบบอื่นนอกเหนือจากนี้

## Fix 4 — ย้ายวันประกาศงบขึ้นบนสุดของ §15

**เหตุผล:** วันประกาศงบเป็นตัวกำหนดอายุของทุกตัวเลขใน section แต่ตอนนี้ถูกซ่อนอยู่ใน footnote ท้ายสุด

- อ่านจาก `nextEarnings` ของ ticker (field เดิม **อ่านอย่างเดียว**)
- แสดงข้างป้าย `forwardView ณ YYYY-MM` ที่หัว section
- รูปแบบ: `งบถัดไป ~26 ส.ค. 2026 · อีก 11 วัน` — ถ้า `nextEarnings` เป็นรูปแบบ `YYYY-MM` ให้แสดง `~` และบอกเป็นเดือนแทนจำนวนวัน
- ถ้าเหลือ **น้อยกว่า 14 วัน** ให้ป้ายเป็นสถานะเตือน พร้อมข้อความ `ตัวเลขในส่วนนี้จะเปลี่ยนหลังงบออก`
- ถ้าวันนี้เลย `nextEarnings` ไปแล้ว ให้เตือนว่า `งบออกแล้ว — รอ /thesis-update`

## Fix 5 — แตก footnote ท้าย §15

**อาการ:** footnote เป็นข้อความยาวบรรทัดเดียว ตัวเล็ก อ่านไม่ออก

**แก้เป็น:** รายการแบบพับเก็บได้ (ปิดไว้เป็นค่าเริ่มต้น) หัวข้อ `ที่มาและข้อจำกัดของข้อมูล` แยกเป็นรายการย่อยตามหัวข้อ:

- ที่มาของ consensus (แหล่ง + จำนวนนักวิเคราะห์ + วันที่)
- ฐานการคำนวณ (GAAP / non-GAAP / รวม SBC หรือไม่)
- ข้อจำกัดที่ทราบ (ปีที่อ้างอิงแหล่งเดียว · metric ที่ยืนยันไม่ได้)
- ที่มาของ guidanceTrack

ขนาดตัวอักษรต้องไม่เล็กกว่าข้อความปกติของหน้า

# PART 2 — เพิ่ม field `basis` (ทำหลัง Part 1 ผ่านแล้วเท่านั้น)

**ปัญหา:** footnote ระบุว่า EPS consensus เป็น **non-GAAP** แต่ตาราง KB เป็น **GAAP** ถ้าต่อเป็นเส้นประบนกราฟ §6 เส้นจะกระโดดขึ้นที่รอยต่อโดยไม่ได้เกิดจากธุรกิจดีขึ้น แค่เปลี่ยนวิธีนับ

**Part นี้แตะ `schema.json` และ `SKILL.md` — ใช้กติกาเดียวกับ Prompt A ทุกข้อ**

## 2.1 เพิ่ม field เข้า schema

```
consensus: [
  {
    fy: "FY2027",
    revenue: 261,
    eps: 30.1,
    confidence: "medium",
    basis: "non-GAAP"      // ใหม่: "GAAP" | "non-GAAP" | "unknown"
  }
]
```

- optional · ค่าเริ่มต้นเมื่อไม่ระบุคือ `"unknown"`
- ticker เดิมที่ไม่มี field นี้ต้องทำงานได้ปกติ

## 2.2 แก้ SKILL.md

- **ขั้นตอน 2:** เพิ่มรายการค้น — ต้องระบุว่า consensus ที่พบเป็น GAAP หรือ non-GAAP และรวม SBC หรือไม่
- **ขั้นตอน 3:** ถ้าระบุไม่ได้ให้ใส่ `"unknown"` ห้ามเดา
- **ขั้นตอน 5:** validate ว่า `basis` เป็นหนึ่งใน 3 ค่าที่กำหนด

## 2.3 แก้การวาดเส้นประบนกราฟ §6

- ถ้า `basis` ของ consensus **ตรงกับ** ฐานของข้อมูล actual ใน KB → ต่อเส้นประจากจุดสุดท้ายตามปกติ
