# Prompt B — ชั้น UI: เพิ่ม 3 section ในหน้า Investment Thesis

> **ต้องรัน Prompt A (`A-thesis-forward-data-prompt.md`) ให้เสร็จก่อน**
> Section C ในไฟล์นี้อ่านจาก `forwardView` ที่ Prompt A เป็นคนสร้าง
> ถ้ายังไม่ได้รัน Prompt A ให้ทำแค่ Section A กับ B แล้วหยุดรายงาน

วางทั้งบล็อกด้านล่างนี้ให้ Claude Code ได้เลย

---

## บริบทโปรเจกต์

เว็บ Investment Thesis (`/thesis`) เป็น static site ใน `public/` runtime เป็น deterministic ล้วน
ไฟล์ที่เกี่ยวข้อง:

- `public/thesis.html` — หน้าเว็บ + cache-bust `?v=YYYYMMDD-th-N`
- `public/thesis-data.js` — curated knowledge base (structural judgment, ประทับ `asOf`)
- `public/thesis-engine.js` — `TE.compute(ticker, {}, {data, mega, regime, R})`
- `scripts/thesis-smoke-test.js` — smoke test

## งาน

เพิ่ม **3 section ใหม่ ต่อท้าย section สุดท้ายที่มีอยู่** ในหน้า Investment Thesis
ทั้งสาม section เป็น **presentation + computation layer เท่านั้น**

## ขอบเขต — ห้ามทำ (สำคัญที่สุด)

โปรเจกต์นี้มี skill `/thesis-update` เป็นเจ้าของ data pipeline อยู่แล้ว งานนี้ต้องไม่ทับซ้อน

- **ห้ามแก้ `public/thesis-data.js`** ทุกกรณี
- **ห้ามแก้ `schema.json`** หรือเพิ่มคีย์ curated ใหม่
- `fundamentals` ต้องคงไว้ 10 คีย์เดิม · `competitive.factors` ต้องคงไว้ 8 คีย์เดิม
- **ห้ามคำนวณทับหรือ override `fundamentals.valuation`** — section ใหม่คือ "หลักฐานประกอบ" ของ score ที่ curate ไว้ ไม่ใช่ตัวแทน ถ้าตัวเลขที่คำนวณได้ขัดกับ score ที่ curate ไว้ ให้ **แสดงทั้งสองค่าคู่กันแล้วติดป้ายว่าไม่สอดคล้อง** ไม่ต้องเลือกข้าง
- **ห้ามแตะ `whatChanged`** — section ใหม่ต้องไม่แสดงข้อมูล QoQ ซ้ำกับที่มีอยู่
- **ห้ามใช้คำ Buy/Sell/ควรซื้อ/ควรขาย/น่าเข้า** ในทุกข้อความ ใช้ภาษาบรรยายสภาพเท่านั้น
- **ห้าม commit** จนกว่าผู้ใช้จะสั่ง "put git"

## กติกาที่ต้องทำตาม

- ภาษาไทยธรรมชาติ (ticker / ชื่อผลิตภัณฑ์ / ชื่อ metric สากลเป็นอังกฤษได้)
- ค่าประมาณต้องนำหน้าด้วย `~` เสมอ
- **ห้ามมโนตัวเลข** ถ้าข้อมูลไม่พอให้แสดงสถานะ "ข้อมูลไม่พอ" พร้อมบอกว่าขาดอะไร ห้าม fallback เป็นค่าเริ่มต้นเงียบ ๆ
- ตามธีมเดิมของหน้า (dark, accent เดิม) ใช้ component / helper ที่มีอยู่ก่อนสร้างใหม่
- ทุก section ต้องรองรับกรณี `TE.compute()` คืน `available: false`

## Phase 0 — สำรวจก่อน แล้วหยุดรายงาน

**อย่าเพิ่งเขียนโค้ด** ทำสามอย่างนี้แล้วรายงานกลับมาก่อน:

1. หา section สุดท้ายในหน้า `/thesis` ว่าอยู่ตรงไหนในไฟล์ไหน และ pattern การ render ของ section เป็นแบบใด (template string / DOM builder / helper อะไร)
2. สำรวจว่า **แหล่งข้อมูลจริงมีอะไรบ้าง** สำหรับสิ่งเหล่านี้ — ระบุ path + ชื่อ field จริง:
   - งบการเงินรายปีย้อนหลัง (revenue, EPS, net income, FCF, CapEx, share count) ย้อนได้กี่ปี
   - ราคาปิดย้อนหลัง (รายวัน/รายสัปดาห์) ย้อนได้กี่ปี
   - market cap / shares outstanding ปัจจุบัน
   - ราคา benchmark (QQQ หรือเทียบเท่า)
   - อัตราผลตอบแทนพันธบัตร 10 ปี
3. บอกว่า **ตัวไหนมี ตัวไหนไม่มี** — ตัวที่ไม่มีจะถูกซ่อนหรือแสดงเป็น "ข้อมูลไม่พอ"

รายงานผลแล้วรอยืนยันก่อนลงมือ Phase 1

## Phase 1 — Section A: บริบทมูลค่า

**การ์ดตัวเลขแถวบน** (ซ่อนการ์ดที่คำนวณไม่ได้ ไม่ต้องแสดงเป็นขีด)

| การ์ด | สูตร |
|---|---|
| P/E (trailing) | ราคาล่าสุด ÷ EPS 12 เดือนล่าสุด |
| FCF yield | FCF 12 เดือนล่าสุด ÷ market cap ปัจจุบัน |
| ส่วนต่าง vs พันธบัตร | FCF yield − ผลตอบแทนพันธบัตร 10 ปี (หน่วย pp) |

**แถบ P/E percentile**

- ใช้ P/E ย้อนหลังยาวที่สุดเท่าที่มี **ต้องระบุจำนวนปีที่ใช้จริงบนหน้าจอ** เช่น `อิงข้อมูล 6 ปี`
- ถ้ามีน้อยกว่า 5 ปี ให้แสดงแถบเป็นสถานะ disabled + ข้อความ "ช่วงข้อมูลสั้นเกินไป ค่า percentile จะบิดเบือน"
- แถบแนวนอน มีเส้นชี้ตำแหน่งปัจจุบัน ป้ายซ้าย/กลาง/ขวา = ต่ำสุด / มัธยฐาน / สูงสุด
- แสดง percentile เป็นจำนวนเต็ม

**แถวเชื่อมกับ curated score** — บรรทัดเดียว เทียบ `fundamentals.valuation` score กับ percentile ที่คำนวณได้ ถ้าทิศทางขัดกัน (score บอกถูกแต่ percentile สูง หรือกลับกัน) ให้ติดป้ายเตือนพร้อมข้อความว่าอาจเกิดจากช่วงข้อมูลอ้างอิงต่างกัน

## Phase 2 — Section B: เงินสด vs การลงทุน

**กราฟเดียว แกน y เดียว หน่วย % ทั้งคู่ — ห้ามใช้ dual axis เด็ดขาด**

- แท่ง: CapEx ÷ รายได้ รายปีงบการเงิน
- เส้นประ: FCF ÷ กำไรสุทธิ รายปีงบการเงิน
- แสดงเท่าที่มีข้อมูลครบทั้งคู่ ปีที่ขาดตัวใดตัวหนึ่งให้ข้าม ไม่ใช่เติมศูนย์

**การ์ดสรุปใต้กราฟ**

| การ์ด | สูตร | หมายเหตุ |
|---|---|---|
| ช่องว่าง CAGR | Revenue CAGR − FCF CAGR (pp) | ขนาดของ capex cycle เป็นตัวเลขเดียว |
| CapEx/รายได้ ล่าสุด vs ค่าเฉลี่ย 3 ปี | ผลต่าง pp | บอกว่ากำลังเร่งลงทุนหรือชะลอ |

ถ้ามีข้อมูล SBC ให้เพิ่มการ์ด `SBC ÷ รายได้` ถ้าไม่มีให้ข้ามไปเงียบ ๆ ห้ามประมาณเอง

## Phase 3 — Section C: ความคาดหวังข้างหน้า

section นี้อ่านจาก `forwardView` ที่ Prompt A สร้างไว้ — **อ่านอย่างเดียว ห้ามเขียนกลับ**
ถ้า ticker ไม่มี `forwardView` ให้ซ่อนทั้ง section

section นี้ **ห้ามแสดงข้อมูล QoQ** เพื่อไม่ให้ซ้ำกับ `whatChanged`

### C1 — EPS revision trend

- อ่าน `forwardView.estimateHistory` กรองเฉพาะ `fy` ล่าสุด แล้ววาดเป็นเส้นเล็ก (sparkline) เรียงตาม `asOf`
- แสดงตัวเลขข้างเส้น: การเปลี่ยนแปลงจากแถวแรกถึงแถวล่าสุดของ `fy` นั้น เป็น % พร้อมทิศทางขึ้น/ลง
- ถ้ามี **น้อยกว่า 2 แถว** ให้แสดงข้อความ "ยังไม่มีประวัติพอ — ต้องรัน `/thesis-update` อีกอย่างน้อย 1 ครั้ง" ห้ามวาดเส้นจากจุดเดียว
- ระบุจำนวนแถวและช่วงเวลาที่ใช้จริงใต้เส้น เช่น `อิง 3 จุด · 2026-02 ถึง 2026-08`

### C2 — ประวัติ guidance

- อ่าน `forwardView.guidanceTrack` แสดงเป็นแถบบล็อกเล็กเรียงจากเก่า (ซ้าย) ไปใหม่ (ขวา) หนึ่งบล็อกต่อหนึ่งไตรมาส
- สีตาม `result`: beat / inline / miss / noGuidance (noGuidance ใช้สีเทาจาง)
- **ห้ามใช้สีอย่างเดียวสื่อความหมาย** ต้องมี label หรือสัญลักษณ์กำกับ และมี legend
- hover/tap แต่ละบล็อกแสดง: ไตรมาส · metric · guided · actual · magnitudePct

**การ์ดสรุปใต้แถบ — ต้องมีครบสามใบ**

| การ์ด | สูตร |
|---|---|
| อัตราส่วน beat | นับ `result: beat` ÷ จำนวนแถวที่ไม่ใช่ `noGuidance` |
| ค่ากลางของ magnitude | median ของ `magnitudePct` เฉพาะแถวที่ไม่ใช่ `noGuidance` |
| ความสม่ำเสมอ | ส่วนเบี่ยงเบนมาตรฐานของ `magnitudePct` |

ใต้การ์ดใส่บรรทัดตีความหนึ่งบรรทัด ตามเงื่อนไขนี้:

- beat ratio สูง (≥80%) **และ** median magnitude ต่ำ (≤2%) → `"guidance ตั้งค่อนข้างระมัดระวัง — beat สม่ำเสมอแต่ขนาดเล็ก"`
- beat ratio สูง **และ** median magnitude สูง (>5%) → `"ผลจริงเกิน guidance อย่างมีนัยต่อเนื่อง"`
- beat ratio ต่ำ (<50%) → `"ผลจริงต่ำกว่า guidance บ่อย — guidance มีความน่าเชื่อถือจำกัด"`
- นอกเหนือจากนี้ → `"ผลจริงใกล้เคียง guidance เป็นส่วนใหญ่"`

**ห้ามเขียนข้อความตีความนอกเหนือจากสี่แบบนี้ และห้ามแปลผลเป็นคำแนะนำใด ๆ**

ถ้าจำนวนแถวที่ไม่ใช่ `noGuidance` มีน้อยกว่า 4 ให้ซ่อนการ์ดสรุปทั้งชุดและแสดงเฉพาะแถบ พร้อมข้อความ `ข้อมูลน้อยเกินสรุป`

### C3 — ต่อเส้น consensus บนกราฟหลัก

แก้กราฟ INDEXED เดิมที่อยู่ด้านบนของหน้า (ไม่ใช่สร้างกราฟใหม่):

- ต่อเส้น revenue และ EPS ด้วย **เส้นประ** ไปยังปีใน `forwardView.consensus` ใช้วิธี index เดียวกับข้อมูลจริง (ปีแรก = 100)
- เส้นประต้องต่างจากเส้นทึบชัดเจน: dash pattern + ความทึบต่ำกว่า + จุดปลายเป็นวงกลมกลวง
- ป้ายกำกับปีที่เป็น consensus ต้องมีเครื่องหมายแยก เช่น `FY2026 (คาด)`
- `confidence: "low"` ให้ลดความทึบลงอีกขั้น และเพิ่ม tooltip บอกที่มา
- legend ต้องมีรายการแยกสำหรับเส้นคาดการณ์ ไม่ใช้ legend ร่วมกับเส้นจริง

**ข้อบังคับที่พังง่ายที่สุด — ตรวจให้แน่:**

> ค่าจาก `forwardView.consensus` **ห้ามเข้าไปในการคำนวณ CAGR badge ทุกตัว** (Revenue CAGR / EPS CAGR / FCF CAGR / Price CAGR) และห้ามเข้าไปในตาราง FY ด้านล่าง

ให้แยกโครงสร้างข้อมูลของ actual กับ consensus ออกจากกันตั้งแต่ต้นทาง อย่ารวมเป็น array เดียวแล้วค่อยกรองตอนคำนวณ

### C4 — ป้ายอายุข้อมูล

- แสดง `forwardView.asOf` ที่หัว section โดยใช้ component ป้ายอายุข้อมูลเดิมของหน้า
- ถ้า `forwardView.asOf` เก่ากว่าเดือนปัจจุบันเกิน 3 เดือน ให้ป้ายเป็นสถานะเตือน + ข้อความ `consensus อาจล้าสมัย`
- ถ้าวันนี้เลย `nextEarnings` ไปแล้วแต่ `forwardView.asOf` ยังไม่อัปเดต ให้เตือนว่า `มีงบออกหลังวันที่ประทับข้อมูลนี้`

## Validate ก่อนส่งงาน

ต้องผ่านทุกข้อ:

- `node --check` ผ่านทุกไฟล์ที่แก้
- `node scripts/thesis-smoke-test.js` ผ่านทั้งหมด (ต้องไม่มี test เดิมพัง)
- `git diff --stat` ต้อง **ไม่มี** `public/thesis-data.js` และ `schema.json`
- ทดสอบ ticker ที่ข้อมูลครบ 1 ตัว และ ticker ที่ข้อมูลไม่ครบ 1 ตัว — ตัวหลังต้องไม่พัง ไม่มี `NaN` `undefined` `Infinity` โผล่บนหน้าจอ
- ค้นหาคำต้องห้ามในไฟล์ที่แก้: `Buy` `Sell` `ควรซื้อ` `ควรขาย` `น่าเข้า` ต้องไม่เจอ
- bump `?v=` ใน `public/thesis.html` เป็นรูปแบบ `YYYYMMDD-th-N` ถัดไป

**การตรวจเฉพาะของ Section C — ต้องทำจริง ไม่ใช่อ่านโค้ดผ่าน ๆ:**

- จดค่า CAGR badge ทั้ง 4 ตัวก่อนแก้กราฟ แล้วเทียบหลังต่อเส้น consensus — **ต้องเท่าเดิมทุกตัว**
- ตาราง FY ด้านล่างต้องมีจำนวนแถวเท่าเดิม ไม่มีปี consensus โผล่เข้ามา
- ทดสอบ ticker ที่ไม่มี `forwardView` — section C ต้องหายไปทั้งก้อน ไม่ใช่แสดงกรอบเปล่า
- ทดสอบ ticker ที่ `estimateHistory` มีแค่ 1 แถว — ต้องขึ้นข้อความ ไม่ใช่วาดเส้น

## ส่งงาน

เปิด `http://localhost:4173/thesis` ให้ผู้ใช้ตรวจ แล้วสรุป:

- section ไหนแสดงได้ครบ / ตัวไหนขึ้น "ข้อมูลไม่พอ" เพราะขาด field อะไร
- ticker ไหนที่ curated valuation score ขัดกับ P/E percentile ที่คำนวณได้
- ยืนยันว่า CAGR badge ทั้ง 4 ตัวมีค่าเท่าเดิมหลังต่อเส้น consensus
- ย้ำว่า **ยังไม่ commit**
