# 9arm — รีวิวความถูกต้องของโค้ด

## หลักคิดเดียว

**ไม่เชื่อคำโฆษณา — เชื่อการรัน**

"คำโฆษณา" ในโค้ดคือ: comment · ชื่อฟังก์ชัน · ชื่อตัวแปร · "เทสต์ผ่านแล้ว" · "ผมเช็คแล้ว" · label บนหน้าจอ
ทั้งหมดนี้เป็น**คำอ้าง** ไม่ใช่หลักฐาน หน้าที่ของรีวิวคือหาว่าคำอ้างกับของจริงตรงกันไหม

บั๊กที่แพงที่สุดไม่ใช่บั๊กที่ทำให้ระบบล่ม — คือบั๊กที่ให้**เลขผิดออกมาสวยๆ** แล้วคนเอาไปตัดสินใจ

## ห้ามทำ 3 ข้อ

1. **ห้ามสรุปว่า "ถูก" เพราะอ่านโค้ดแล้วดูถูก** — ต้องรันหรือหาหลักฐานภายนอกมายืนยัน
2. **ห้ามสรุปว่า "ถูก" เพราะเทสต์ผ่าน** — ถามก่อนว่าเทสต์นั้น assert อะไร เทสต์ที่ assert ผิดจุดผ่านได้ทุกครั้ง
3. **ห้ามอ้อม** — บอกตรงๆ ว่า **พังจริง / ไม่พัง / ยังพิสูจน์ไม่ได้** ห้ามใช้คำว่า "อาจจะ" เพื่อเอาตัวรอด ถ้ายังไม่รู้ให้เขียนว่ายังไม่รู้ พร้อมบอกว่าต้องรันอะไรถึงจะรู้

## 7 คลาสบั๊ก "เลขผิดเงียบๆ" (เจอจริงในโปรเจกต์นี้)

ไล่ทุกข้อกับโค้ดที่รีวิว ทีละข้อ

| # | คลาส | อาการจริงที่เคยเจอ | วิธีจับ |
|---|---|---|---|
| 1 | **coercion กลืน null** | `Number(null)=0` · `Number(" ")=0` · `Number([])=0` ทำให้ผลรวม TTM EPS ต่ำกว่าจริง แต่ไม่ error เลย (เจอซ้ำ 3 ที่) | หา `Number(` / `parseFloat` / `+x` ทุกจุดที่รับข้อมูลนอก แล้วยิงค่า `null, undefined, "", " ", [], {}, NaN` เข้าไป |
| 2 | **ฐาน % คนละตัว** | น้ำหนักหุ้นคิดจาก "เงินที่ลงแล้ว" แต่คอลัมน์เป้าคิดจาก "พอร์ตทั้งก้อน" → QQQM โชว์ 56.6% ที่จริง 40% | ทุกที่ที่มี `/ total * 100` ถามว่า total ตัวนี้คือก้อนเดียวกับที่เอาไปเทียบไหม · ตรวจว่าผลรวมได้ 100% |
| 3 | **ปัดเศษก่อนคำนวณสถิติ** | เก็บ P/E แบบ round 2 ตำแหน่งแล้วเอาไปหา median/percentile → classification พลิกที่ขอบเกณฑ์ | ปัดเศษต้องอยู่ชั้น**แสดงผล**เท่านั้น · สถิติต้องกินค่าดิบ |
| 4 | **แสดงค่าที่หมายความว่าโกหก** | ค่าปัจจุบันหลุดนอกช่วงอ้างอิง แต่โชว์ `percentile 0` เหมือนอยู่ในช่วง | หาเคสขอบ (นอกช่วง / เท่าค่าสุด / ชุดข้อมูลว่าง / 1 จุด) แล้วดูว่า**ข้อความที่ออกจอ**ยังจริงไหม |
| 5 | **cache เก่าโชว์เป็นของสด** | 2 เครื่องโหลดพร้อมกันได้เลขต่างกัน เพราะ localStorage/CDN/serverless-`/tmp` แยกกัน 3 ชั้น และหน้าไม่แสดงวันของข้อมูล | ไล่ทุกชั้น cache · ถามว่า "ผู้ใช้รู้ได้ไหมว่าเลขนี้ ณ วันไหน" ถ้าไม่รู้ = บั๊ก |
| 6 | **ทางเดินข้อมูลคนละสาย** | หน้า A อ่าน action จาก `recommendAction` หน้า B คำนวณสด `actionFromSignal` → หุ้นตัวเดียวกัน หน้าหนึ่งบอกขาย อีกหน้าบอกซื้อ | เลขเดียวกันที่โชว์หลายที่ ต้อง trace ว่ามาจากฟังก์ชันเดียวกันจริง แล้วรันทั้งสองเส้นด้วย input เดียวกันเทียบ |
| 7 | **ลำดับกติกาต่างกัน** | ที่หนึ่งเช็ค REVIEW ก่อน SELL อีกที่เช็ค SELL ก่อนแล้ว `return` → กติกาหลังไม่มีโอกาสทำงาน | กติกาชุดเดียวกันที่เขียนซ้ำสองที่ ให้ไล่**ลำดับ** + หา `return` ที่ตัดกติกาถัดไปทิ้ง |

## ขั้นตอน

1. **หาคำอ้าง** — comment/ชื่อ/label/เทสต์ บอกว่าโค้ดนี้ทำอะไร จดไว้
2. **ไล่ 7 คลาสข้างบน** กับโค้ดจริง
3. **พิสูจน์ด้วยการรัน** — เขียน `node -e` ยิง input จริง + input ขอบ · ถ้าเป็นเลขที่อ้างแหล่งภายนอก (ราคา/งบ) ให้ไปดึงแหล่งจริงมาเทียบ ไม่เชื่อค่าใน repo
4. **เทียบก่อน/หลัง** ถ้าเป็นการแก้ไข — ค่าที่ไม่ควรขยับต้องขยับ 0 (พิสูจน์ ไม่ใช่เชื่อ)
5. **สรุปแบบไม่อ้อม** (ฟอร์แมตล่าง)

## ฟอร์แมตสรุป

```
พังจริง (ต้องแก้)
  <ไฟล์:บรรทัด> — <อาการที่ผู้ใช้จะเห็น> · input ที่ทำให้พัง: <ค่า> · ที่ควรได้: <ค่า>

ไม่พัง (ตรวจแล้ว)
  <สิ่งที่ตรวจ> — พิสูจน์ด้วย: <คำสั่ง/ผลลัพธ์>

ยังพิสูจน์ไม่ได้
  <สิ่งที่ค้าง> — ต้องรัน/หาอะไรถึงจะรู้
```

ทุกบรรทัดใน "พังจริง" ต้องมี input ที่ทำให้พัง — ถ้าเขียน input ไม่ได้ ให้ย้ายไปช่อง "ยังพิสูจน์ไม่ได้"

## โทนการเขียน

ตรงไปตรงมา ไม่ประชด ไม่ด่าคน — ด่าโค้ด · อธิบายให้คนที่ไม่ได้เขียนโค้ดนี้ก็เข้าใจว่าพังยังไงและกระทบอะไร · ไม่ใช้ศัพท์สวยๆ ที่ไม่มีเนื้อ ("robust", "clean", "ดูดี") · เลขทุกตัวที่พูดถึงต้องบอกที่มา

## Red flags — เจอคำพวกนี้ในรีวิวของตัวเอง = ยังรีวิวไม่เสร็จ

- "ดูแล้วน่าจะถูก" / "โค้ดอ่านดูโอเค" → ยังไม่ได้รัน
- "เทสต์ผ่านหมด" (แล้วจบ) → ยังไม่ได้ดูว่าเทสต์ assert อะไร
- "อาจมีปัญหาถ้า..." → ลองให้เกิดจริงหรือเปล่า ถ้าไม่ ให้ย้ายไป "ยังพิสูจน์ไม่ได้"
- "แก้แล้วน่าจะไม่กระทบอะไร" → ยังไม่ได้เทียบก่อน/หลัง
- ไม่มีเคสขอบเลยในรีวิว → คลาส 4 ยังไม่ได้ตรวจ

## เกร็ดจากโปรเจกต์นี้

เทสต์ในโปรเจกต์นี้เคย**ผ่านทั้งที่ตัวเทสต์เองผิด** (ใช้ index ไตรมาสผิดตอนหาผลรวมรายปี → ได้ 142.93 vs 122.4 แล้วเกือบสรุปว่าข้อมูลพัง) — เวลารีวิวเทสต์ ให้ตรวจ**ตัวเทสต์** ด้วย ไม่ใช่แค่ดูว่าเขียว

คำสั่งที่ใช้พิสูจน์ในโปรเจกต์นี้ได้เลย:
```bash
node scripts/kb-report.js validate <TICKER>   # ตรวจกติกาข้อมูล curated
node scripts/valuation-smoke-test.js          # 68 เคส รวม adversarial
node scripts/kb-report.js regress             # thesis output เทียบ HEAD ต้อง byte-identical
```
